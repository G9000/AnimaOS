# Reviewed external tools

An ordinary Anima agent can use reviewed MCP tools through anonymous Streamable HTTP or an explicitly started trusted local Windows process. Both use the official Rust SDK, fixed `2025-11-25` protocol and the same owner review, exact grants, Exec approval and action receipts. Saving, listing or restoring a connection starts no transport. Discovery and review make no tool calls and grant no authority. M44 passed its gates and scoped controlled Windows browser/restart acceptance; PR50 is verified merged at `15e40c397a6ef961639e9375fe50ee513d09c9bf`. M45 reviewed community bundles are implemented and locally accepted.

The owner separately adds an exact reviewed alias to the agent's existing tool grants. Every external tool uses the existing Exec approval category; server hints cannot lower its classification. Helpers inherit no MCP grants. The native dispatcher captures the full reviewed descriptor, live connection generation and grant epoch before approval, then rechecks them before dispatch and before accepting the result.

## Owner API

All operations are scoped to one existing ordinary agent at `/api/agents/{agent_id}/mcp-connections`. They use the existing local-owner authorization and return `Cache-Control: no-store`.

| Operation                  | Request                                                             | Result                                                                       |
| -------------------------- | ------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| GET collection             | none                                                                | Own saved configuration and current runtime state                            |
| POST collection            | `label` and exactly one of `endpoint` or `stdio: {executable,args}` | Disabled version-one connection; no endpoint/process start                   |
| GET connection             | none                                                                | One own connection                                                           |
| PATCH connection           | `expectedVersion` and `label`, `enabled`, or HTTP `endpoint`        | Saved compare-and-swap edit; local launch is immutable                       |
| POST connection/connect    | `expectedVersion`                                                   | Initialize and complete bounded discovery                                    |
| POST connection/discover   | `expectedVersion`                                                   | Refresh current connection discovery                                         |
| POST connection/review     | `expectedVersion`, `discoveryId`, `descriptorDigest`                | Save one exact reviewed descriptor; no grant                                 |
| POST connection/disconnect | `expectedVersion`                                                   | Retire runtime transport; keep reviewed metadata and grants                  |
| DELETE connection          | `expectedVersion`                                                   | Save removal and remove only this connection's aliases from the owner grants |

Unknown fields, explicit null patch fields and empty patches are rejected. Endpoints allow HTTPS or literal loopback HTTP (`127.0.0.1`/`::1`), without user information, query strings, fragments, redirects or ambient proxy use. M65 adds one owner-entered static Bearer credential for HTTPS Streamable HTTP connections. OAuth, refresh, arbitrary headers, shell command strings, environment/cwd settings and package installation remain unsupported.

Aliases contain the connection UUID and a descriptor-digest prefix. The full immutable digest is checked as well; a collision is rejected. Changed remote schemas/descriptions produce a new ungranted alias. Endpoint or enabled edits retire live discovery; a label-only edit keeps discovery while advancing the saved version. Old reviews remain dormant when their exact descriptor is absent.

## Trusted local Windows processes

Choose Local process in Connectors, enter an installed absolute `.exe` path and an ordered argument vector, and confirm trust in that exact program/arguments. Saving stays disabled. Enable connection saves configuration; Start local server explicitly launches it. Each editor line is one literal argument: spaces/quotes have no shell meaning, untouched empty text means no arguments, and Pass one empty argument explicitly represents `[""]`. Changing launch input clears the trust choice. Saved executable/arguments cannot be edited; remove the connection and save a new one. Label/enabled edits remain available.

The API rejects missing/both transport inputs, explicit nulls, unknown fields, relative/empty executable values, control characters and known shell/package-manager launchers. Bounds are 2,048 UTF-8 bytes for the executable, 32 arguments, 2,048 bytes each and 16 KiB combined executable/argument content. Direct spawning clears inherited environment except fixed `SystemRoot`/`WINDIR` and uses a daemon-owned private TempDir working directory. No PATH search, shell interpolation, env map, cwd override, install/update or ambient provider configuration is supported. These controls do not sandbox the trusted executable.

Execution is Windows-only because whole-job descendant exit must be witnessed. Other hosts return unavailable before executable lookup, reservation or spawn. Existing HTTP connections remain portable. Public views add `transport: streamableHttp|stdio` and `stdio: null|{executable,args}`; `endpoint` stays a string and is empty for stdio. Durable HTTP rows retain their previous shape.

## Limits and recovery

- Four connections across the workspace; 32 durable reviews per connection, including dormant reviews.
- Five seconds for initialization plus complete first discovery; at most four pages and 64 candidate tools.
- Twenty seconds for one call, including queueing; one physical call per connection, two globally and at most four queued callers.
- Aggregate raw wire budget 256 KiB, individual JSON/SSE event 64 KiB, including raw comments and progress traffic.
- Reviewed descriptor/schema pair and arguments each 16 KiB, depth 16 and 1,024 nodes. Schemas use explicit Draft 2020-12, acyclic local `$defs` references and safe numeric values.
- Final model evidence envelope at most 16 KiB and 16 text blocks. Unsupported blocks and shortened content are explicitly marked. Returned text is external evidence with connection, generation, alias and digest provenance.

There is no automatic retry, reconnect, protocol fallback, stale discovery cache or additional model lookup. A timeout, Stop or revocation cannot prove that a remote effect was undone. A retired physical call keeps its slot until owned cleanup joins. Unknown cleanup retains its quarantine; shutdown can report unsettled effects without reusing the slot.

The four configured connections and global call/queue limits are shared by HTTP and stdio. A cached factory also retains at most four stdio child leases, including startup, retirement and quarantine; deleted configuration cannot free an unjoined child. Stdout is bounded before SDK decoding to 64 KiB per JSON-RPC line and 256 KiB per owned operation, with a separate 256 KiB unsolicited idle allowance. Malformed/oversized/invalid output maps to static errors; stderr is continuously discarded and never enters model results or owner diagnostics. Stop, disconnect, disable, delete, shutdown and revocation retain physical resources until owned protocol/sends/readers and the Windows whole-job wait join; uncertainty remains quarantined.

Control-plane version 18 retains existing HTTP metadata/reviews/grants and adds optional immutable stdio launch records. Version-17 migration has an independent `.pre-mcp-stdio.bak`, preserving the earlier `.pre-mcp.bak` for version 16. Restart restores every transport disconnected, with no network/process start, automatic retry or reconnect. Only explicit connect and exact rediscovery can restore readiness. Candidate saves settle through the existing ordered control-plane path before shared publication. Precommit failure preserves old metadata; uncertain post-replacement durability retains the candidate fail-closed and reports unavailable.

## Owner console and grant settlement

M43 adds a typed SDK client and an owner panel in Connectors. Owners can add or edit a connection, explicitly enable and connect it, refresh discovery, inspect and review one exact candidate, then separately grant or revoke its alias. The panel displays saved configuration, review state, readiness and permission separately. It does not contact endpoints on mount, retry mutations, or provide a button to invoke a remote tool. Settings and MCP changes continue to use the existing agent grant list; ordinary unrelated Settings edits preserve MCP aliases, while choosing a standard profile remains an explicit whole-list replacement.

Granting or revoking one alias uses `PATCH /api/agents/{agent_id}/mcp-connections/{connection_id}/grants/{alias}` with `{expectedVersion,descriptorDigest,granted}`. The response is `{connection,granted,toolNames}`. The server checks the owner, current connection version and exact full digest of the reviewed alias, then changes only that alias in the current agent configuration. An effective change increments that connection's version and invalidates old dispatch stamps; an identical desired state is a checked no-op that preserves the version and `None` versus `Some([])` tool-list state. It never calls the remote server. Stale requests return a conflict for explicit refresh and reconfirmation.

Grant candidates save before publication through the ordered control-plane path. Precommit failure leaves the prior grant and record in place. Durability uncertainty publishes the observed candidate fail-closed, retires the affected transport and returns unavailable; the UI must not describe this as rollback or resubmit automatically. A bounded acknowledgement merges only aliases from an older snapshot, preserving current-version owner edits, native grants and other connections. Revoking an alias fences active dispatch; an already-running physical call keeps its slot until cleanup finishes, and revocation cannot prove that a remote effect was undone.

PAR-04 remains partial. M44 Windows stdio, M45 declarative MCP/skill bundle installation/update, and M65 explicit HTTPS static Bearer credentials are implemented with scoped local acceptance. Non-Windows stdio, OAuth/refresh, arbitrary headers, compiled connector contributions and selected real-server acceptance remain open. These milestones do not establish arbitrary-server safety, useful task quality or whole Hermes parity. The implementation reuses the official Rust MCP SDK and maintained process-wrap ownership; public Hermes source informed lifecycle comparison, without importing private profiles or copying its Python runtime. See the [bundle guide](community-bundles.md) for exact owner bindings, pending adoption, lifecycle CAS, global skill scope and cleanup limits.

### Owner-managed HTTPS Bearer credentials (M65)

Bundle removal deletes credential slots only for its exact owned removal set, including its dormant predecessors. Disable and retained rows outside the removal set keep their slots. If any deletion fails or is uncertain, removal intent and all row references remain for review; already completed deletions are not rolled back.

On an HTTPS Streamable HTTP connection, an owner can explicitly save or replace a static Bearer token, or clear it. The password is entered only in the owner control; connection list/get exposes `hasBearerCredential` as a saved-reference indicator. It does not read the OS vault or establish that the credential is available, accepted, or that the server is healthy. The token is stored in the OS credential vault and bound to that connection's exact HTTPS endpoint. Editing the endpoint clears the binding, so enter the token again for the new endpoint.

Credential changes retire and join the active connection before mutation. A failed or uncertain result requires the owner to refresh the connection view and decide whether to re-enter or clear the credential; the console does not retry, reconnect, or replay a mutation. Explicit connect/discovery and separate tool grants remain separate owner actions. Stdio and unauthenticated HTTP connections are unchanged; OAuth, refresh, arbitrary headers, and the unsupported GET event-stream path remain unavailable. Native and UI acceptance uses synthetic credentials and local TLS only.
