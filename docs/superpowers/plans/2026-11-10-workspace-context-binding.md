# Optional workspace companion and per-agent context implementation plan

> Execute with the subagent-driven-development workflow, followed by independent spec and code review. User approved same-chat default-personality fallback and per-agent access. No live credentials, grants, provider prompts, commits or publication are needed to test the implementation.

**Goal:** A selected AnimaOS agent can adopt an independently hosted M.O.T.H.E.R persona and use its durable memory; other agents can receive selected context without adopting identity. Offline operation preserves the same conversation and restores configured local personality.

**Architecture:** M.O.T.H.E.R enforces additive owner-created client access policies without changing v1 canonical records or legacy grants. AnimaOS has an opt-in generic MCP workspace-context binding, stored in per-agent settings, with current connection/run authority and workspace/generation/subject pinning. No AnimaOS dependency enters M.O.T.H.E.R's store or protocol; its existing optional setup adapter can configure the owner-selected binding.

## Contract

- Existing grants remain legacy-compatible; no automatic privilege expansion or migration of real clients.
- Owner-created `companion` grant: full canonical context plus owner persona; principal `subject` bound to a specific external agent identifier. `shared` grant: explicit allowlist of record IDs (empty means none), no persona, no canonical write scopes; optionally reviewed proposals. Policy absent means existing legacy behavior, but legacy grants cannot activate companion identity.
- `mother_get_context` adds `access: { version: 1, mode: "legacy" | "companion" | "shared", subject: string | null }`. Existing workspace identity/generation remains canonical. Restricted clients see only allowed records and corresponding inventory, search, retrieval, references, unsettled-work and proposal/receipt surfaces; semantic retrieval must not leak unauthorized results or counts. Recheck policy on each request and before publication. Do not expose persona through shared search/context. Preserve export/restore semantics: client policies are credential authority, excluded from portable exports/restores like client grants. Malformed policy fails closed; companion access never grants write scopes. Existing receipts/proposals recheck current record visibility; denied content returns a generic failure without replaying mutations.
- AnimaOS per-agent `settings.additional.workspaceContext`: `{connectionId, tool: "mother_get_context", mode: "companion" | "shared", workspaceId, generation, subject}`. This is host-owned opt-in configuration; the key stays in the MCP connection's private configuration, never model arguments. Other conforming workspace tools can be selected without a hardcoded MOTHER dependency in core.
- At each model request, refresh bounded context through the same reviewed MCP connection, under current run/agent permissions. Validate exact pinned workspace/generation, subject equals current agent, expected mode, bounded nonempty persona/hash for companion, and JSON shape. An unrelated/wrong/stale/revoked connection must never install identity. An owner-saved binding authorizes the bounded bootstrap read without another Ask prompt, but never overrides an explicit policy Deny. Remote grant/persona/policy changes must be observed before the next request, not only on a new chat turn. Once a read fails, stay offline for that run; bounded recovery is attempted on the next turn. No borrowed grant or identity in delegated/helper runs.
- Companion mode replaces only transient personality with the current returned persona; memory remains attributed reference data. It uses workspace durable memory as primary: suppress competing automatic local-memory recall and canonical local-memory write tools in this mode, including offline fallback; keep conversation persistence and other ordinary runtime safety controls. Memory capture uses existing MOTHER proposal/direct-write tools according to its grant; do not silently mirror writes, replay unknown operations or claim offline persistence.
- If unavailable/invalid, restore the complete configured local personality in the same chat and supply a clear unavailable-memory status. Never use a cached remote persona as current. Existing chat history remains; no transcript deletion or new session. Recovery retries only bounded read at the next turn; never replay mutations.
- Reuse existing MCP connection version/wire generation/grant epoch stamps; recheck current authority after bootstrap and before publishing the model request. Invalid or mismatched bindings withhold that connection's model-callable MCP tools for the run, including search/write, so fallback cannot bypass failed binding validation. Companion primary-memory isolation covers background task-result capture and external turn/write mirroring as well as model tools and automatic recall.
- The independent Mother owner TUI selects shared/companion/legacy mode, creates the per-agent key/allowlist and configures the pinned host binding without manual IDs or secret copying into AnimaOS. AnimaOS owner Profile UI displays the mode/connection and can remove the binding using an exact revision. No credentials in UI responses. Key revocation and connection removal remain explicit independent operations; disabling identity alone does not revoke an existing MCP key.
