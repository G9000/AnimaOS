# M67 granted workspace document reads — lean plan

> For agentic workers: use the controller's source-only, disjoint implementation workflow. This is a lean plan: exact interfaces, owned files, meaningful RED, focused tests and gates; implementation code only where an API is tricky.

**Status:** bound before source. Branch `g9000/companion-workspace-documents-m67` from verified M66/PR72 main `98a7b2cd860246b1e505a0fd9128bdd0e332f22b` (tree `f96256f0c1d967127ac8128b0967722bdc53a15c`). Root commands and source-only disjoint workers; first meaningful RED, then implementation. No services/models/accounts activated.

**Goal:** an explicitly granted `read_document` tool reads one existing workspace `.docx`, `.pdf` or `.xlsx` and returns bounded source-cited untrusted text with honest coverage, without uploading the file or granting shell access.

**Architecture:** add a native tool handler around existing capability-relative file opening and `DocumentExtractor`/`DocumentWorker`. Reuse M54–M66 parsers and typed extraction; retain the physical worker's process-wide slot, limits and cleanup. Add one opt-in owner checkbox through existing agent tool configuration, not a new API or document subsystem.

## Evidence and reuse decision

- `hosts/rust-daemon/src/tools/filesystem/search.rs::read_workspace_file_from_root` currently uses `fs::read_to_string`; binary Office/PDF documents cannot be read through `read_file`. Keep that tool's behavior intact.
- `tools/workspace_bytes.rs::WorkspaceBytes::open` captures a held root through nofollow capabilities. `read_instruction_file(relative,max)` already opens each component safely, bounds reads by opened-handle size and max+1, and rejects nonregular/linked/replaced sources. `read_bounded(relative,max,expected)` requires a known expected size. Reuse the former bounded-open/read implementation through a generic name/helper; do not add canonicalize-then-ambient-read logic or obtain authority from a caller size.
- `attachments/documents/worker.rs::DocumentExtractor::extract(format,bytes,cancel,deadline)` already provides the required seam. `DocumentWorker` uses the fixed worker mode, Windows physical limits and one shared process slot; other hosts return unavailable. No new process program or parser path is needed.
- `attachments/documents/admission.rs::read_source` retains one of four physical read leases inside each blocking task after cancellation. Its closure/record types are attachment-specific; share its small retained-read-pool mechanism with the new source reader rather than invent an unbounded blocking queue. Do not change attachment ownership/admission rules.
- `tools.rs::ToolExecutionContext::execute_tool` already performs configured/live checks, approval and action-journal begin/revalidate/finish. Context carries `workspace_root`, `cancel`, `run_link` and approvals. `agent_runs.rs` owns an injectable `Arc<dyn DocumentExtractor>` and passes the run stop signal into context. Reuse these seams.
- `runtime.rs::content_from_tool_result` preserves successful `Content.text` and adds ordinary tool metadata; return ordinary tool text, not forged attachment records or the reserved `documentExtracts` key.
- The owner console has fixed profile sets plus individual opt-ins (`SettingsPanel.tsx`, e.g. `read_conversation_window`). Merely registering a tool would leave no normal UI to enable it. Add one opt-in without changing standard profile defaults or unrelated tool selections.

Reuse alternatives: importing Hermes Python/file-conversion runtime or a separate process adapter adds dependencies and duplicate ownership controls; a new Rust parser duplicates M66. Select direct reuse of Anima's existing bounded worker/parser and a narrow native tool adapter. Public pinned Hermes `1fd18277267152893a8a24792b79213e7ca3f899` cached `skills/productivity/xlsx/SKILL.md` describes reading existing paths and separate formula/cached views; its source record is `.superpowers/sdd/2026-10-16-companion-xlsx-m66/hermes-public-source.json`. This is behavioral reference only. No upstream execution or code copy; retain existing `HERMES-NOTICE` unchanged. No private Hermes installation/profile access.

## Proposed interfaces to bind before source tests

### Tool and grants

- Name: `read_document`; strict object arguments `{ file_path: string }`, required, no additional properties. Workspace-relative forward-slash path, 1–1,024 UTF-8 bytes; reject controls, absolute/UNC/drive/ADS paths, empty/dot/parent components and backslashes. Preserve literal names rather than silently trimming them into another file.
- Infer only `.docx`, `.pdf`, `.xlsx` case-insensitively. The selected parser verifies actual bytes. No caller MIME, executable, format override, OCR flag, URL, directory traversal or batch input.
- Classify as `RiskClass::Read` in `approvals/policy.rs`; existing configured grants and approval rules still apply. Add no automatic grant to old agents, profiles, helpers or connectors.
- Scope follows the existing granted filesystem tools, including helper and connector-triggered coordinator runs. Require a configured workspace root and a present run cancellation signal; missing lifecycle context refuses before filesystem access. Existing configured/live parent/peer authority, approval and action receipts remain authoritative. Do not add an owner-web-only restriction or automatically grant the tool.
- Settings checkbox: **Allow reading workspace documents**, off when absent. Enabling saves only `read_document` plus preserved current grants; unrelated saves do not add it. Standard profile replacement clears the opt-in using the established memory-removal pattern. No tool call, file read or worker starts when the checkbox is saved.

### Native adapter and source identity

- New `tools/workspace_document.rs`: strict arguments, source read, extractor call, result validation, output fitting and errors. Handler uses the standard `ToolHandler` signature.
- Add `document_extractor: Arc<dyn DocumentExtractor>` to `ToolExecutionContext`, defaulting to `Arc::new(DocumentWorker)`, plus `with_document_extractor(...)`. `agent_runs.rs` passes its existing `self.document_extractor` clone so real-handler tests can inject the existing controlled seam. Do not add a user-selectable executable or test-program option.
- Generic safe reader returns owned bytes captured under one held root, with source SHA-256 computed by the daemon. Cap input at existing `MAX_DOCUMENT_INPUT_BYTES` (2 MiB), never trust archive sizes or caller metadata. Use existing SHA implementation/dependency. Preserve the nofollow/nonblocking regular-file checks and exact opened-handle size checks.
- Result is a captured byte snapshot, not a promise that the path remains unchanged: output contains exact relative path and SHA-256 of those captured bytes. The worker receives only format/bytes/cancel/deadline. No automatic second read/parse or current-file freshness claim. Reuse existing filesystem authority: symlinks/reparse points are refused, but ordinary hard links are not newly prohibited and no hard-link isolation claim is made.
- One absolute 10-second deadline includes source read, worker, fitting and any selected recheck; never renew it between phases. Check cancellation before the read and after every await. Physical reads retain bounded leases until the OS read returns; worker retirement remains owned after caller cancellation/drop. No daemon state lock spans disk/process await.
- Share the existing four retained read leases across attachment and workspace-document source reads. No queued `spawn_blocking` work without a physical lease; saturation returns unavailable. Existing one-process worker slot continues to return busy/unavailable without retries.

### Output and bounds

- Success `Content.text` is one serialized JSON envelope: `{ "kind":"workspace_document", "trust":"untrusted_data", "source":{"path":<relative>,"sha256":<hash>}, "extraction":<ExtractedDocumentText> }`. `attachments: None`; no reserved attachment metadata. The extraction version, locators, status, omissions and PDF/XLSX coverage are the existing core types. Path, names and cells remain JSON-quoted data.
- Bound the entire envelope to `MAX_DOCUMENT_RENDERED_BYTES` (16 KiB), including source fields, coverage, escapes and labels. Preserve whole DOCX paragraphs and XLSX cells; PDF may retain the existing UTF-8 prefix. Reuse `fit_document_snapshots` as an internal fitting primitive only: its synthetic fitting row is never exposed as an attachment. Serialize the actual envelope to decide final size; if needed use a bounded binary search over the 0..16,384 fit budget (at most 15 probes), then validate and verify the exact final bytes. No arbitrary slicing of serialized JSON or formula/cache cells. Metadata-only output must also fit; otherwise return a bounded unavailable error. Keep five distinct omission reasons; fitting errors refuse rather than dropping reasons.
- Partial/no-text/unsupported/encrypted/malformed/too-large/unavailable/cancelled outcomes remain honest. A valid extractor failure status can be a successful typed read result with zero blocks; unsafe path, missing grant, stale authority or failed transport return ordinary bounded tool errors. Do not expose OS paths, raw parser stderr or credential-bearing internals in errors.
- These are tool-result bytes, accounted and persisted through existing tool/context/history paths. No attachment hydration, memory write, global index/cache, extraction retry or restart replay. Tests inspect the actual next adapter request, not merely an injected DTO. No new core serialized contract, parser dependency, public route, attachment DTO or download mutation is planned.

## Top five risks for controller rulings

1. **Filesystem authority and snapshot freshness:** document paths bypass attachment ownership but must remain inside the configured held root. Recommend nofollow bounded source reads and content-hash snapshot semantics; decide whether a post-read recheck is necessary. A same-size in-place modification cannot be claimed impossible merely from metadata checks.
2. **Cancellation and physical capacity:** opening documents creates fixed internal-worker work behind a Read tool. Recommend existing explicitly granted filesystem contexts with required cancellation, shared retained read leases, the existing single worker slot and absolute deadline; never release capacity on cancellation while physical work survives.
3. **Output accounting and trust:** coverage/paths/escaping can exceed a plain-text budget or be misrepresented as attachment authority. Recommend a strict host-local quoted envelope, exact full-envelope cap, existing fitting/validation and no reserved attachment metadata. Refuse rather than weaken caps or silently drop reasons.
4. **Actual owner enablement and revocation:** native registration alone is not a daily-use feature, and adding to default profiles would silently expand grants. Recommend a separate explicit checkbox preserving unrelated/custom grants, with existing approval/receipt revalidation and no activation on save.
5. **Scope and evidence inflation:** reusing document parsing does not add OCR, editing, visual fidelity, non-Windows worker support or model-quality acceptance. Recommend one useful finite end-to-end fake-model oracle plus narrow regression cases, reuse existing parser/physical gates, and leave real providers/accounts/services/normal profiles disabled.
