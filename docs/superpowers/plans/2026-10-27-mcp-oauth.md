# MCP OAuth implementation plan

> Implement in this session with bounded implementation agents and independent review. User authorization is already explicit; no additional design approval gate is inferred.

**Goal:** Browser account sign-in for existing HTTP MCP connections, with vault-backed refresh and sign out.

**Design:** [MCP OAuth design](../specs/2026-10-27-mcp-oauth-design.md).

## Tasks

- [x] Protocol crate: write synthetic discovery/PKCE/issuer/refresh tests, run them failing, implement `OAuthSession::begin`, `authorization_url`, `complete`, and serializable redacted `OAuthCredentials` with `access_token`/`revoke`. Use rmcp auth with a bounded network adapter; deny redirects/private discovery and suppress secret-bearing upstream tracing. Own `packages/core-rust/crates/anima-mcp-oauth` and the root Cargo workspace member.
- [x] Daemon: test owner authorization, callback state/replay, cancellation/edit/signout races, vault binding, refresh, and no tool replay. Implement bounded Windows-safe chunked OAuth vault slots with immutable generations and recoverable cleanup; test 2560-byte UTF-16 item limits, large tokens, rotation, restart, signout, partial writes/deletes, and persistence failure preventing dispatch. Add owner route contracts, callback lifecycle, transport token provider, and opaque control-plane references. Preserve endpoint/version/permission fences and existing bearer/stdio behavior. Own `hosts/rust-daemon` integration files and daemon Cargo dependency.
- [x] SDK and web: first test exact encoded owner routes and UI sign-in/cancel/signout/lifetime behavior. Add typed methods in `packages/sdk/src/mcp.ts` and exports; owner transport in `apps/web/src/lib/daemon-api.ts`; focused account controls in `apps/web/src/components/mcp`. Keep callback codes and tokens out of the SDK, owner responses, and settings UI state; the browser delivers the authorization code directly to the daemon's loopback callback. Poll read-only status only during an explicit attempt; no effect retries.
- [x] Review: independent spec/plan review, then implementation review. Resolve important findings with regression tests and rerun affected checks.
- [x] Verification and docs: update `docs/companion/mcp.md` with supported registration, lifecycle, route shapes, limits, and concrete evidence. Run required checks below. Record results in `test-output`; remove only task-owned scratch files after inspection.

## Verification commands

Run focused synthetic protocol and daemon OAuth tests during development, coordinating Cargo target ownership. Final full Rust verification uses `CI=1`, `CARGO_TARGET_DIR=target/cargo/validation-rust-daemon`, and the Visual Studio build environment on Windows:

1. `bun run rust:test` — all core, daemon, and packaged supervisor suites must pass.
2. `bun run rust:lint` — formatting and Clippy must pass.
3. `bun run --filter @animaos/sdk test`, `build`, `typecheck`, `lint` — all must pass, including real-daemon synthetic integration when allowed.
4. `bun run --filter @animaos/web test src/components/mcp/McpConnectionsPanel.test.tsx` and new OAuth test file; `build`, `typecheck`, `lint` — all relevant checks must pass.
5. `git diff --check` and inspect the final diff for accidental secret logging, grants, unrelated edits, and temporary artifacts.

Keep required caches. Do not stop existing user daemons or IDE tooling. Use the existing isolated Cargo validation directory. Live account consent remains unverified unless explicitly completed through the browser.
