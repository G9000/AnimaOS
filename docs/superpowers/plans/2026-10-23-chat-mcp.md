# Chat MCP Setup Implementation Plan

> Execute inline with focused tests and review. Keep unrelated changes intact and leave work unstaged.

**Goal:** Anima can truthfully offer MCP setup in chat and perform that setup with its existing Rust connection manager.

**Architecture:** Add an owner-only native management tool, derive it into ordinary owner chat tool catalogs, and call the existing persisted MCP lifecycle operations. Preserve exact review/grants, approval policy, credential vault, and immutable per-run tool catalogs.

**Tech Stack:** Rust daemon, anima-core tool descriptors, existing MCP SDK transport and control-plane persistence; no new dependencies.

- [x] Add a failing regression for setup-tool visibility on a fresh owner chat without configured MCP servers.
- [x] Add `tools/mcp_management.rs`: strict action parsing, one-server configuration conversion, static error mapping, model-safe connection views, and lifecycle dispatch.
- [x] Register and classify the tool, derive it only for direct owner chat, and revalidate its catalog authority before dispatch.
- [x] Add lifecycle tests for configure/connect/review/grant, failure and denial, cross-owner/upstream refusal, persistence, and use on the next chat.
- [x] Document chat setup and the existing supported transport/authentication limits.
- [x] Run focused and required Rust Nx verification, inspect the diff, and record current validation evidence and limitations.

Review findings were incorporated: setup remains visible with tool discovery enabled; scoped manager operations recheck owner authority after transaction waits and before a delayed transport launch; rejected secret-bearing input is filtered before approval/receipt admission and omitted from live cards. Versioned actions convert the core's floating-point representation only for exact positive safe integers before Rust u64 deserialization.

Scoped diff whitespace checks passed and the verified production-source hashes stayed unchanged through the final run.

They now await stream readiness against one five-second deadline per loop, retaining every existing event assertion and the chunk bound; the focused 15-case suite and final full suite passed. An earlier document-reservation case failed once under the broad run, then passed unchanged in isolation and in the final run; no production document code was changed.
