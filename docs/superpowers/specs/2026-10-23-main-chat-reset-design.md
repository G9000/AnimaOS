# Clear the main conversation

The owner can ask Anima to clear/reset the main web chat without deleting the companion, configuration, other conversations, saved memories, or core memory files. The existing protection against deleting the main session remains.

Add an owner-only native `clear_main_chat` tool. Only a direct owner turn in the companion's own main web chat receives it. The tool records a durable request on its current run and reports that the reset is pending. Once that run settles, the coordinator clears the chat under the existing control-plane transaction and room lock. This prevents an executing runtime from restoring old messages after reset. Do not generate task-result memories or conversation learning from the clearing turn.

The request is stored on the main session with its exact run ID. Admission closes immediately when it is saved. Inputs accepted before that boundary are discarded along with their ledger rows; their workers cannot start without those rows. A persisted generation also invalidates legacy inputs and system follow-ups already waiting for the room. A recovery worker waits for the room lease and retries pending requests after a failed final save or crashed turn. Startup applies saved requests before recovering unstarted turns.

Both request admission and clearing refuse active or unresolved background helpers owned by this chat, keeping their launch lineage intact. Helper acceptance checks pending reset under its own transaction, so a concurrent tool batch cannot launch new work after a reset request is saved.

The shared clear operation preserves the session ID, main designation, title, companion configuration and memory. It removes that room's hot messages, summary/checkpoint/context bookkeeping, session allowances, saved clarification cards and old run records. It durably records a history deletion before queueing removal of mirrored messages and attachments through the existing history outbox. Admission must reject a session while history deletion is pending, so new messages cannot race deletion. Failed saves restore the prior state, including clarification records. Restart recovery must either complete an acknowledged reset request or leave it visibly pending; it must never claim an unfinished reset succeeded.

The outbox removes the deletion marker under the transaction and saves its removal before reopening admission. On acknowledgement-save failure it restores the marker and retains the deletion queue entry for retry. `session.cleared` removes stale browser run activity; a subsequent session update and explicit command refresh reload the empty transcript. The session response exposes the reset generation, which also invalidates side-question cards and late interaction responses under the unchanged session ID. Tool discovery captures this exact control under its own owner/main-chat authority rather than treating it as a shared default grant.

Expose the same idle-chat operation through an owner-authorized HTTP endpoint and web `/clear` and `/reset` commands. Busy chats refuse the direct operation until the reply settles. On success the web refreshes the session, messages and run list; existing empty-page handling clears loaded history. A natural-language request uses the tool and follows the same durable path.

Regression checks cover main-chat scope and owner authority, preservation of companion/memories/other rooms, hot and mirrored history deletion, summary removal, save rollback, repeat clearing, pending-deletion admission, and a model tool call whose final commit cannot restore the old transcript. Web tests cover slash dispatch and refresh. Run the required Rust daemon tests and relevant web tests/build/typecheck.
