# Discord two-way attachments

Implement the approved files/images scope using the existing host attachment pipeline. Voice/video processing is deferred.

Inbound: preserve native attachment metadata from Discord REST messages; admit only messages passing existing author/channel/mention rules, including attachment-only participating-thread messages. Download only admitted attachments, with no bot Authorization on CDN requests, HTTPS exact Discord CDN hosts, no redirects, source channel/attachment ID path binding, bounded streamed bytes/count/aggregate. Save supported images/text/documents through existing upload validation and workspace capability storage. Save scoped history records before advancing the intake cursor; journal attachment IDs with the inbound receipt. Retry download failures without advancing the cursor; deterministic IDs allow reuse of completed saves. Unsupported/oversized/malformed files become explicit input notices, never fabricated content or silent loss. Existing model adapter verifies images and supplies bounded document excerpts; text files remain readable with read_file. Attachment contents are untrusted user data.

Outbound: add send_discord_file(path, caption?) to the existing host-created current-thread capability. Only direct live Discord runs may discover/call it; no caller-selected channel, helper/delegation or web spoofing. Read one bounded regular file relative to the configured workspace, refusing links/traversal; capture bytes before sending, validate filename/content, cap uploads at 10 MiB. Use multipart payload_json/files[0], no mentions, stable tool-call nonce and enforce_nonce. Confirm sent:true only after Discord returns the matching channel, message ID and an attachment with matching filename/size. Use existing owned-effect lifecycle and durable run tool journal; do not automatically retry uncertain effects or replay effects after restart. Definite failure returns a truthful tool error. No persistent pending outbound-file retry queue is needed.

Existing saved journals deserialize with empty attachment IDs. Existing parent auto-thread routing and attribution remain. The bot invite requests Attach Files; existing installations may need that permission granted. Document supported types, limits, workspace/model requirements, current-thread tool usage and failure semantics.

Validation: regression tests for native metadata, multipart receipt/uncertainty, CDN URL boundary and size checks, intake attachment-only/auth routing and restart/dedup, saved content/vision hydration, output scope/path/permission/cancellation/acknowledgement. Run full Rust suites and formatting.
