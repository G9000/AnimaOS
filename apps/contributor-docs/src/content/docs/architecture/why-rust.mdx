The engine and the host are Rust. The TypeScript packages (`sdk`, `cli`, `tui`, `ui`, `apps/web`) are clients. This page records the reasons and the costs. It makes no benchmark claims; where numbers matter, measure.

## Why the Engine Is Rust

**One deployable binary.** The daemon (`anima-daemon`) and the packaged `anima` program are single executables. `anima` embeds the web console and updates itself, which would be much heavier to ship with a JavaScript runtime.

**Predictable resource use for long-lived work.** The daemon holds many things open at once: concurrent agent runs (default limit 8), SSE streams, background processes, PTY app sessions, connector pollers and in-memory memory indexes. A language with no garbage collector makes that footprint easier to reason about.

**Types as contracts.** The core states its boundaries as traits and data types: `ModelAdapter`, `Provider`, `Evaluator`, `DatabaseAdapter`, `MemoryVectorIndex`, `ExternalMemoryProvider`, `ExecutionStore`, `CapabilityExecutor`. Hosts implement them; the engine does not know which implementation it runs against. The compiler enforces that no I/O dependency creeps into `anima-core`: check its `Cargo.toml`. It has no HTTP client, no database driver and no async runtime (`tokio` is a dev-dependency only).

**Safety in code that handles secrets and processes.** The workspace sets `unsafe_code = "forbid"` (root `Cargo.toml`). The daemon manages credentials, child processes and filesystem writes on the owner's behalf; ownership and borrowing rules remove whole classes of data races and use-after-free bugs from that code. Where the OS offers no safe API (for example putting a Windows ConPTY child in a Job Object), the code documents the limit instead of reaching for `unsafe`: see [Coding Apps and Helpers](/hosts/rust-daemon/coding/).

## Pure Core, Real Host

`anima-core` and `anima-memory` operate on in-memory values and traits. The memory manager serializes to a `MemoryManagerSnapshot` that the host persists (JSON, SQLite or Postgres); the core never touches a file.

```rust
// the host decides where these bytes go
let snapshot = manager.snapshot();
```

Not every crate is I/O-free. `anima-model-adapters` makes HTTP calls with `reqwest`, `anima-process` spawns processes and PTYs, `anima-acp` talks to child processes, and `anima-worktree` drives the `git` CLI. They are in `packages/core-rust` because other hosts could reuse them, not because they are pure. See [Rust Core](/architecture/rust-core/).

## Why Not Everything in Rust

| Layer                   | Language   | Reason                                                 |
| ----------------------- | ---------- | ------------------------------------------------------ |
| Engine and host         | Rust       | Single binary, long-lived process, explicit boundaries |
| SDK, CLI, TUI           | TypeScript | Familiar async patterns, Ink for terminal UI           |
| Web console, playground | TypeScript | React ecosystem, Vite tooling                          |
| Docs sites              | Astro      | Starlight                                              |

The SDK owns the request/response types shared by the CLI, TUI and UI. A client in another language only needs the daemon's HTTP/SSE contract (`/openapi.json` on a running daemon).

## Trade-offs

- **Compile times.** Rust builds are slower than TypeScript transpilation, and the daemon pulls in heavy dependencies (SQLite, an ONNX embedding runtime via `fastembed`, an MCP client). Use `cargo check -p <crate>` for fast feedback and `cargo test -p <crate>` for a single crate; use the Bun workspace scripts for full validation.
- **Packaging.** Native binaries per platform. The release pipeline builds `aarch64-apple-darwin` and `x86_64-pc-windows-msvc` (see `dist-workspace.toml`).
- **Contributor ramp-up.** The core uses `async_trait` and trait objects heavily; start with [AgentRuntime](/architecture/rust-core/anima-core/agent-runtime/).
