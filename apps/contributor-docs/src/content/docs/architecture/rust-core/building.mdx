## Building

### Prerequisites

- Rust stable (via [rustup](https://rustup.rs))
- [cargo-nextest](https://nexte.st) (optional)
- Bun, for the Nx targets

### Commands

Run from the repo root. The Cargo workspace is the root `Cargo.toml`; there is no `packages/core-rust/Cargo.toml`.

```bash
# Preferred: the Nx targets build and test exactly the eleven core crates
bun x nx run core-rust:build
bun x nx run core-rust:test
bun x nx run core-rust:lint        # cargo fmt --check for those crates

# Direct cargo, one crate
cargo check -p anima-core
cargo test -p anima-memory
cargo test -p anima-swarm

# Everything, including the daemon and the packaged program
cargo test --workspace
```

`core-rust:build` and `core-rust:test` share the workspace Cargo cache under `target/cargo`, avoiding duplicate dependency builds. They build `anima-core`, `anima-service-adapters`, `anima-model-adapters`, `anima-memory`, `anima-schedule`, `anima-swarm`, `anima-harness`, `anima-document-content`, `anima-process`, `anima-acp` and `anima-worktree`. Adding a crate means updating the `-p` lists in `packages/core-rust/project.json` as well as the root `Cargo.toml` `members`.

### Workspace Facts

- `edition = "2021"`, `license = "MIT"`, shared `version`, and `[workspace.lints.rust] unsafe_code = "forbid"`.
- `anima-memory` has a `locomo-eval` feature that compiles the LoCoMo benchmark cases; the daemon enables it.
- `anima-core` has no async runtime dependency; test code uses `tokio` as a dev-dependency.

## Testing

```bash
# Core crates through Nx
bun x nx run core-rust:test --skipNxCache

# One module
cargo test -p anima-memory memory_manager::tests

# Memory evaluation harness and benchmarks
bun x nx run core-rust:memory-eval --skipNxCache
bun x nx run core-rust:memory-locomo --skipNxCache
```

Other `core-rust` targets run Node test oracles: `browser-worker-test` and the `coding-acceptance-*`, `coding-reliability-test`, `provider-task-acceptance-test` and `research-acceptance-test` targets (see [Testing](/workflow/testing/)).

Testing rules: no real provider calls (use a mock `ModelAdapter` or `DeterministicModelAdapter`), no real credentials, deterministic assertions, and fake transports for anything networked. `anima-model-adapters` tests spin up local `axum` servers.

### Mocking a ModelAdapter

```rust
struct Scripted(Vec<ModelGenerateResponse>);

#[async_trait]
impl ModelAdapter for Scripted {
    fn provider(&self) -> &str { "scripted" }
    async fn generate(&self, _c: &AgentConfig, _r: &ModelGenerateRequest)
        -> Result<ModelGenerateResponse, String> {
        Ok(self.0[0].clone())
    }
}

#[tokio::test]
async fn run_returns_the_reply() {
    let mut runtime = AgentRuntime::new(config, Arc::new(Scripted(vec![end_response("hi")])));
    let result = runtime.run(Content { text: "hello".into(), ..Content::default() }).await;
    assert_eq!(result.status, TaskStatus::Success);
}
```

`stream` falls back to `generate`, so a `generate`-only mock exercises the full loop.

## Adding a Model Provider

Providers live in [anima-model-adapters](/architecture/rust-core/model-adapters/#adding-a-provider), not in the daemon. For an OpenAI-compatible endpoint it is one `ProviderDefinition` in `catalog.rs`; the daemon builds its configuration from `provider_definitions()` and routes automatically. Only a new wire format needs a new body builder, parser and stream consumer.

## Adding a Tool

- **Embedding in your own program:** implement `HarnessTool` and register it on the [harness](/architecture/rust-core/anima-harness/).
- **In the daemon:** tools are native handlers registered in `hosts/rust-daemon/src/tools/`. A new tool also needs a risk class in `approvals/policy.rs` (`READ_TOOLS`, `WRITE_TOOLS`, `EXEC_TOOLS`, `NETWORK_TOOLS` or `DELEGATE_TOOLS`); a tool the table does not name defaults to the exec class, and a test checks that every registered tool is classified. Optional high-impact tools are granted per agent, never by default.

## Adding a Swarm Strategy

A strategy is a `CoordinatorStrategyFn` passed to `SwarmCoordinator::with_hooks`. See [Strategies](/architecture/rust-core/anima-swarm/strategies/#custom-strategies). A new built-in also needs a `SwarmStrategy` variant, a branch in `resolve_strategy`, and the daemon's string parsing in `routes/contracts/swarms.rs`.

## CI

CI does not call cargo directly. `.github/workflows/ci.yml` runs `nx format:check` and `bun x nx run-many -t lint test build typecheck e2e-ci`, which includes `core-rust` and `rust-daemon` through their targets. Run the same Nx targets locally before pushing.
