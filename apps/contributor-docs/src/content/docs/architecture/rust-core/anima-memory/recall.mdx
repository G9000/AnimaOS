---
title: Recall Fusion
description: How lexical, vector, relationship, temporal, recency and importance signals become one ranking
---

`MemoryManager::recall` fuses several candidate sources into one ranked list. It returns a plain `Vec`, not a `Result`.

```rust
pub fn recall(&self, query: &str, opts: MemoryRecallOptions) -> Vec<MemoryRecallResult>;
pub fn recall_with_vector_index(&self, query, opts, vector_index: Option<&dyn MemoryVectorIndex>) -> Vec<MemoryRecallResult>;
pub fn recall_with_vector_index_filtered(&self, query, opts, vector_index, visible: impl Fn(&Memory) -> bool) -> Vec<MemoryRecallResult>;
```

The `_filtered` form takes a host `visible` predicate (ownership, hidden-text and similar rules). It is applied to every candidate source, so an ineligible memory cannot take a slot from an eligible one.

## Candidate Sources

| Source | Where candidates come from | Raw signal |
|--------|----------------------------|-----------|
| Lexical | BM25 search over the filtered set, up to `lexical_limit` (default `4 * limit`) | Score divided by the best score in this query, so 0 to 1 |
| Vector | The supplied `MemoryVectorIndex` (`search_filtered`, up to `lexical_limit`); only finite positive hits are kept | Score divided by the best vector score in this query |
| Recency | `get_recent_filtered` up to `recent_limit` (default `limit`) | `1 / rank`, the newest memory scoring 1.0 |
| Relationship | Evidence memories of agent relationships selected by `entity_id` or the agent id, up to `relationship_limit` (default 20) | `min(strength * confidence, 1)` |
| Temporal | Evidence of **active, currently valid** temporal facts about `entity_id`, up to `temporal_limit` (default `limit`), when the query looks like a fact question | The fact's `confidence` |
| Importance | The memory's stored `importance` | 0 to 1 |

A temporal fact is considered only if the query's terms overlap the fact's predicate or value, or overlap its subject **and** the query has fact intent (terms such as `current`, `favorite`, `prefer`, `status`, `remember`, or any in `temporal_intent_terms`). A fact with no evidence pointers falls back to scanning memories whose text mentions both its subject and its predicate or value (scored at 0.85 of the fact's confidence), but only while the store holds at most 5,000 memories.

## Final Score

```
vector_weight' = lexical_score > 0 ? w_vector * (1 - lexical_score) : w_vector

score = w_lexical      * lexical_score
      + vector_weight' * vector_score
      + w_relationship * relationship_score
      + w_temporal     * temporal_score
      + w_recency      * recency_score
      + w_importance   * importance_score
```

Default `MemoryRecallWeights`:

| Signal | Weight |
|--------|--------|
| lexical | 0.55 |
| vector | 0.15 |
| relationship | 0.20 |
| temporal | **0.00** |
| recency | 0.05 |
| importance | 0.05 |

Temporal evidence is collected and reported, but contributes nothing to the score unless a caller passes `weights: Some(MemoryRecallWeights { temporal: .. , .. })`. Vector weight shrinks as an exact lexical match gets stronger, so a strong keyword hit is not drowned by a loosely related vector hit.

Results are sorted by `score` descending (ties: newer `created_at`, then id) and truncated to `limit` (default 10). Each `MemoryRecallResult` carries the `memory`, the `score` and the six components (`lexical_score`, `vector_score`, `relationship_score`, `temporal_score`, `recency_score`, `importance_score`), each clamped to 0 to 1.

## Context Selection

`select_context(opts, visible)` and `select_context_with_vector_index(opts, vector_index, visible)` choose memories to put in an agent's prompt, with different rules from `recall`:

- Eligible: the agent's own `Fact` and `Reflection` memories with no `world_id` or `session_id`, `Room`-scoped ones only for the current room, and whatever `visible` allows.
- **Lexical first:** rank by how many distinct query terms (stop words removed, at most 32) a memory contains, then importance, then newest. Memories with zero overlap are skipped. Duplicates (same text after whitespace and case normalization) collapse to the best one.
- **Then semantic:** spare slots, up to `limit`, are filled with eligible vector hits with positive finite scores that are not duplicates.

## Weights Are Per Query

`MemoryRecallOptions` is the tuning surface: `search` filters, `entity_id`, `agent_id`, the four limits, `temporal_intent_terms` and `weights`.

## Snapshot Boundary

```rust
pub fn snapshot(&self) -> MemoryManagerSnapshot;
pub fn replace_snapshot(&mut self, snapshot: MemoryManagerSnapshot);
```

The snapshot has the five record collections only. The BM25 index is rebuilt on `replace_snapshot`; vectors are the host's to restore. Serialization format and storage are the host's choice: the daemon persists through its memory store (see [Persistence](/hosts/rust-daemon/persistence/)).
