`packages/core-rust` holds the reusable Rust crates. The governing rule is **core defines behavior, hosts provide reality**. `anima-core` has no HTTP client, database driver or async runtime, and `anima-memory`, `anima-swarm` and `anima-schedule` add no I/O of their own. A host (today `hosts/rust-daemon`) supplies the real world: provider calls, persistence, credentials, connectors.

The crates live under `packages/core-rust/crates/` and build in the root Cargo workspace. From the repo root:

```bash
bun x nx run core-rust:build
bun x nx run core-rust:test
```

## Dependencies Between Crates

```
anima-core ◀── anima-memory ◀── anima-swarm
    ▲   ▲
    │   └── anima-service-adapters ◀── anima-document-content
    │             ▲
    └── anima-model-adapters ◀── anima-harness
anima-process ◀── anima-acp          anima-worktree        anima-schedule
```

Arrows point at the dependency: `anima-swarm` depends on `anima-core` and `anima-memory`; `anima-model-adapters` depends on `anima-core` and `anima-service-adapters`; `anima-process`, `anima-worktree` and `anima-schedule` do not depend on other animaOS crates (except `anima-acp` on `anima-process`).

## Two Execution Paths in `anima-core`

1. **`AgentRuntime`**, the loop the daemon uses today. It runs a task in a room, streams model output through a `RunObserver`, executes tools through a host-supplied closure, runs evaluators, and records events. See [AgentRuntime](/architecture/rust-core/anima-core/agent-runtime/).
2. **`DurableAgentEngine`**, a portable engine over an `ExecutionStore`, `CapabilityRegistry` and `PolicyEngine` with leases, approvals, pause/resume and recovery records. It is covered by core tests and by an integration test in `anima-model-adapters`; the daemon does not use it. See [Durable Engine](/architecture/rust-core/anima-core/durable-engine/).

## Design Rules

1. **No I/O in `anima-core`.** It never opens sockets, files or database connections. Do not add an HTTP framework, DB driver or runtime-specific dependency.
2. **Trait boundaries.** External concerns are traits: `ModelAdapter`, `DatabaseAdapter`, `Provider`, `Evaluator`, `MemoryVectorIndex`, `ExternalMemoryProvider`, `ExecutionStore`.
3. **Host-owned persistence.** `AgentRuntime::snapshot()` / `from_snapshot()` and `MemoryManager::snapshot()` / `replace_snapshot()` return plain data; the host decides where it is stored and what is restored. No crate resumes a model call mid-turn.
4. **Reusable code lives in `packages/`.** If another host could use it, it does not belong in `hosts/rust-daemon`.
5. **Small, deterministic algorithms.** BM25, cosine similarity and recall fusion are implemented in `anima-memory` with no ML dependency; real embeddings are supplied by the host through `MemoryVectorIndex`.

## Where Things Went

Anything that talks to a provider over HTTP is in `anima-model-adapters`, not in `anima-core` or in the daemon. The daemon's `RuntimeModelAdapter` routes a call to the right adapter; its provider key pool (`KeySource`) and `FallbackModelAdapter` add key rotation and per-agent fallback models. See [Model Adapters](/architecture/rust-core/model-adapters/).
