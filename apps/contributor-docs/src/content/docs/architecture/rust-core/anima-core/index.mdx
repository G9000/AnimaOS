---
title: anima-core
description: Agent runtime, trait interfaces and portable contracts, with no I/O
---

`anima-core` is the execution crate. It owns `AgentRuntime` (the task loop the daemon runs), the events it emits, the traits that separate the engine from the outside world, and a set of portable, validated contracts (context-window selection, completion review, task records, durable execution, capability, policy and memory ports). It has **no I/O**: no HTTP, filesystem, database or LLM client code, and no async runtime dependency (`tokio` is a dev-dependency only). Its non-test dependencies are `async-trait`, `futures`, `futures-timer`, `serde`, `serde_json`, `jsonschema`, `serde_jcs`, `sha2` and `uuid`.

## What Each Area Does

| Area | Purpose |
|------|---------|
| `agent`, `primitives` | The vocabulary: what an agent is (`AgentConfig`, `AgentState`), what flows through it (`Content`, `Message`, `TaskResult`). |
| `model`, `model_error` | `ModelAdapter` with `generate` and a streaming `stream` method; `classify_model_error` reads a provider error string back into a `ModelFailureKind` so hosts can rotate keys and fall back. |
| `components` | Extension hooks: `Provider` (context before each run) and `Evaluator` (accept, retry or abort a final answer). |
| `persistence` | `DatabaseAdapter` for tool-step records, which lets a retried request reuse completed tool results. |
| `runtime` | `AgentRuntime`, `RunObserver` / `RunFrame` live frames, `RunControl` (stop signal and steering inbox), run deltas for concurrent rooms. |
| `context_window` | `select_context`: which earlier messages fit a token budget, with an optional summary standing in for older turns. |
| `completion` | `CompletionReview`: bounded, advisory verification evidence before a final answer. |
| `agent_files` | Pure rendering of host-accepted `SOUL.md` / `AGENTS.md`-style files into prompt text. Discovery and filtering stay in the host. |
| `structured_tasks`, `tool_rpc`, `external_tools`, `filesystem_checkpoints` | Portable bounds and bookkeeping. Hosts own grants, authentication, dispatch and persistence. |
| `communication` | `AgentCommunicationRoute`: lineage for synchronous agent-to-agent requests, max 3 hops and 12 requests, cycles rejected. |
| `definition`, `capability`, `policy`, `execution`, `engine` | The durable engine and its contracts. See [Durable Engine](/architecture/rust-core/anima-core/durable-engine/). |

## Architecture Flow

```
┌───────────────────┐   AgentRuntime::new(config, adapter)
│  Host (daemon)    │──────────────────────────────────────┐
└───────────────────┘                                      ▼
        ▲                      ┌──────────────────────────────────────────────┐
        │ TaskResult           │ run_in_room_with_context_and_tools(room, ...)│
        └──────────────────────│  providers → system prompt → model.stream()  │
                               │  tool calls → host closure → loop            │
                               │  evaluators → accept / retry / abort         │
                               └──────────────────────────────────────────────┘
                                    │               │               │
                               ModelAdapter     Provider       Evaluator
```

1. The host creates an `AgentRuntime` from an `AgentConfig` and an `Arc<dyn ModelAdapter>`.
2. It optionally attaches providers, evaluators, a `DatabaseAdapter`, a `RunObserver` and a `RunControl`.
3. It calls one of the `run*` methods, passing a closure that executes tool calls.
4. The runtime talks to traits only. The host provides the concrete implementations.

## Design Rules

1. **No I/O.** All I/O happens in host-provided trait implementations.
2. **Trait boundaries.** The runtime never knows which LLM, database or tool registry is behind a trait.
3. **Snapshots are data.** `AgentRuntimeSnapshot` holds state, messages, the newest 500 events (`MAX_RETAINED_EVENTS`), the event count, the last task and the step counter. `AgentRuntime::from_snapshot` rebuilds a runtime; adapters, listeners, providers and evaluators are not part of it and must be re-attached. No mid-turn resume exists in the core.
4. **Room-scoped conversations.** Each run happens in a room (`room-N` for `run`, or a host-chosen id), so unrelated tasks do not share history.
5. **Bounded everything.** Tool rounds, evaluator retries, retained events and every portable record have explicit limits.

## Lifecycle

```
Idle ──▶ Running ──▶ Completed
              │
              ├──▶ Failed
              └──▶ Terminated   (stop())
```

`AgentStatus` has five variants: `Idle`, `Running`, `Completed`, `Failed`, `Terminated`. A cooperative run stop is separate: it ends the run as a `TaskResult` error whose message is `"stopped"` (`RUN_STOPPED_ERROR`) and leaves the agent `Idle`, not `Failed`.
