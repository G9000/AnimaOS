`anima-core` defines the traits that form the boundary between the engine and the host. Each is `Send + Sync` and uses `async_trait`, so hosts can implement them with async I/O without the core knowing.

## ModelAdapter

File: `packages/core-rust/crates/anima-core/src/model.rs`.

```rust
#[async_trait]
pub trait ModelAdapter: Send + Sync {
    fn provider(&self) -> &str;

    async fn generate(
        &self,
        config: &AgentConfig,
        request: &ModelGenerateRequest,
    ) -> Result<ModelGenerateResponse, String>;

    /// Default: call generate and emit its result as one Final frame.
    async fn stream(
        &self,
        config: &AgentConfig,
        request: &ModelGenerateRequest,
        sink: &dyn ModelStreamSink,
    ) -> Result<(), String> { /* default provided */ }
}
```

`ModelAdapter` is the only required dependency of `AgentRuntime`. **The runtime always calls `stream`**; an adapter that only implements `generate` still works through the default.

```rust
pub struct ModelGenerateRequest {
    pub system: String,            // assembled system prompt
    pub messages: Vec<Message>,    // conversation so far
    pub temperature: Option<f64>,
    pub max_tokens: Option<u32>,
}

pub struct ModelGenerateResponse {
    pub content: Content,
    pub tool_calls: Option<Vec<ToolCall>>,
    pub usage: TokenUsage,
    pub stop_reason: ModelStopReason,   // End | ToolCall | MaxTokens
}

pub enum ModelStreamFrame {
    TextDelta(String),
    Usage(TokenUsage),                  // provider-reported so far; each replaces the last
    Served { provider: String, model: String, reason: String }, // a fallback answered
    Final(ModelGenerateResponse),       // required: a stream without it fails the run
}
```

`TokenUsage` carries `prompt_tokens`, `completion_tokens`, `total_tokens`, `cached_prompt_tokens` (included in prompt) and `reasoning_tokens` (included in completion). Errors are plain `String`s; adapters format them predictably (`"{Provider} API error ({status}): {body}"`, optional trailing `(retry after Ns)`) so `classify_model_error` can read a `ModelFailureKind` back out: rate limited, overloaded, billing, auth failed, model not found, timeout, transport, context too long, bad request or other.

Real implementations live in [anima-model-adapters](/architecture/rust-core/model-adapters/), not in the core and not in the daemon.

## Provider

File: `components.rs`.

```rust
#[async_trait]
pub trait Provider: Send + Sync {
    fn name(&self) -> &str;
    fn description(&self) -> &str;
    fn priority(&self) -> u8 { 0 }                       // higher runs earlier
    fn refresh_each_model_request(&self) -> bool { false }
    async fn get(&self, runtime: &AgentRuntime, message: &Message)
        -> Result<ProviderResult, String>;
}

pub struct ProviderResult {
    pub text: String,
    pub metadata: Option<BTreeMap<String, DataValue>>,
}
```

Providers inject dynamic context under `## Context` as `[name]: text`. By default each provider is called once per run and its text is reused; set `refresh_each_model_request` for context that must be reread. An `Err` fails the run.

The daemon registers two providers for every agent (`components.rs`): `recent_memories` (relevant saved memories for the owner's message, lexical first, topped up with semantic matches, bounded to six records) and `local_time`.

## Evaluator

```rust
#[async_trait]
pub trait Evaluator: Send + Sync {
    fn name(&self) -> &str;
    fn description(&self) -> &str;
    fn priority(&self) -> u8 { 0 }
    fn requires_tool_budget(&self) -> bool { false }
    async fn validate(&self, runtime: &AgentRuntime, message: &Message) -> Result<bool, String>;
    async fn evaluate(&self, runtime: &AgentRuntime, message: &Message, response: &Content)
        -> Result<EvaluatorResult, String>;
}

pub struct EvaluatorResult {
    pub decision: EvaluatorDecision,   // Accept | Retry { feedback } | Abort { reason }
    pub score: Option<f64>,
    pub follow_up: Option<Content>,
    pub metadata: Option<BTreeMap<String, DataValue>>,
}
```

Evaluators run after the model's final (non-tool) response, in descending priority. `validate` returning `false` skips the evaluator for this message. The first non-`Accept` decision wins:

- `Retry { feedback }` records the earlier draft marked `revised`, adds a system message `Evaluator requested a revision: ...` and regenerates. At most **2** retries (`MAX_EVALUATOR_RETRIES`); the next one fails the run with `evaluator retry limit exceeded`.
- `Abort { reason }` fails the run with that reason.
- An evaluator error fails the run.

`requires_tool_budget() == true` marks a corrective pass that needs tools; such evaluators are skipped during the tool-free budget wrap-up.

`EvaluatorResult::accept()`, `retry(feedback)` and `abort(reason)` are the usual constructors. The daemon no longer ships a per-reply memory evaluator; memories come from tools and reviews.

## DatabaseAdapter

File: `persistence.rs`. Optional.

```rust
#[async_trait]
pub trait DatabaseAdapter: Send + Sync {
    async fn write_step(&self, step: &Step) -> PersistenceResult<()>;
    async fn get_step_by_idempotency_key(&self, agent_id: &str, key: &str)
        -> PersistenceResult<Option<Step>>;
    async fn list_agent_steps(&self, agent_id: &str) -> PersistenceResult<Vec<Step>>;
}

pub struct Step {
    pub id: String,
    pub agent_id: String,
    pub step_index: i32,
    pub idempotency_key: String,
    pub step_type: String,                    // "tool"
    pub status: StepStatus,                   // Pending | Done | Failed
    pub input: Option<serde_json::Value>,
    pub output: Option<serde_json::Value>,
}
```

`PersistenceError` has `Connection`, `Write` and `Query` variants. Failures are non-fatal to a run. The daemon's implementation is `SqlxPostgresAdapter` (Postgres mode, table `step_log`). The crate's in-memory adapter exists only under `cfg(test)`.

## Other Boundaries

| Trait | Where | Purpose |
|-------|-------|---------|
| `ContextTokenEstimator` | `context_window.rs` | Estimate message cost for `select_context` |
| `RunObserver` | `runtime/observer.rs` | Receive live `RunFrame`s |
| `ModelStreamSink` | `model.rs` | Where an adapter writes stream frames |
| `MemoryPort`, `DocumentPort`, `RetrieverPort`, `ArtifactPort` | `memory.rs`, `evidence.rs` | Storage-neutral contracts for durable memory and evidence (not used by the daemon's `MemoryManager`) |
| `ExecutionStore`, `CapabilityExecutor`, `CapabilityReferenceValidator` | `execution/`, `capability.rs` | The [durable engine](/architecture/rust-core/anima-core/durable-engine/) |

## Host vs Core

```
Host: impl ModelAdapter (RuntimeModelAdapter), impl DatabaseAdapter (SqlxPostgresAdapter),
      event listener → SSE, RunObserver → live stream, tool closure → tool registry
                                  │
                            trait boundary
                                  │
Core: AgentRuntime calls adapter.stream(), db.write_step(), provider.get(),
      evaluator.evaluate(), observer.on_frame(), listener(event)
```

The core knows what to do (run the loop); the host decides how (which LLM, which store, which transport).
