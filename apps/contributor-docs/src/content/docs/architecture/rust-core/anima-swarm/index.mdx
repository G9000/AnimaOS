---
title: anima-swarm
description: Multi-agent coordination with a coordinator, strategies and an in-memory message bus
---

`anima-swarm` coordinates a manager agent and a set of workers. It depends on `anima-core` (and `anima-memory`), runs on `tokio` (sync primitives) and `futures`, and does no I/O of its own. It never builds agents itself: the host supplies an **agent factory** that turns an `AgentConfig` into a runnable agent shell.

## Module Structure

```
src/

├── message_bus.rs       # MessageBus
├── types.rs             # SwarmConfig, SwarmState, SwarmStatus, SwarmStrategy, AgentMessage, ...
└── strategies/

    ├── supervisor.rs
    ├── round_robin.rs
    └── dynamic.rs
```

## SwarmConfig

```rust
pub struct SwarmConfig {
    pub strategy: SwarmStrategy,                  // Supervisor | Dynamic | RoundRobin
    pub manager: AgentConfig,
    pub workers: Vec<AgentConfig>,
    pub max_concurrent_agents: Option<usize>,     // admission cap on live agents; None = unlimited
    pub max_parallel_delegations: Option<usize>,  // default: workers.len().max(1)
    pub max_turns: Option<usize>,                 // default: workers.len() + 1
    pub token_budget: Option<u64>,                // observed per-dispatch budget; None = unlimited, 0 blocks all runs
}
```

`max_turns` means different things per strategy: round-robin turns, supervisor delegations (it becomes the manager's tool-iteration cap) or dynamic `choose_speaker` calls. `token_budget` is observed, not enforced preemptively: the host calls a budget check before model requests, and requests already in flight can overshoot. It is not a billing cap.

## SwarmCoordinator

```rust
let coordinator = SwarmCoordinator::with_hooks_and_message_events(
    config, strategy_fn, agent_factory, Some(message_events),
);
coordinator.start().await?;                 // spawn and pool the workers
let result = coordinator.dispatch("task").await;   // or dispatch_content(Content)
let state = coordinator.get_state();        // SwarmState snapshot
coordinator.stop().await?;                  // stop agents, clear the bus
```

Constructors: `new()` (an unconfigured default that errors if you try to run it), `with_config(config)` (the built-in strategy, but the default factory **refuses** to build agents), `with_hooks(config, strategy, factory)`, `with_hooks_and_message_events(..)` and `with_recovered_state_and_hooks(config, state, ..)` for restoring a saved `SwarmState` (usage sealed, no live agents).

- `start()` builds every worker through the factory in parallel and puts them in a pool; on any failure it stops the ones it built and returns the first error.
- `dispatch*` takes a dispatch lock (one task at a time per swarm), sets `Running`, resets task state, runs the strategy, captures token usage, stops **non-pooled (ephemeral) agents**, and records the result. The status after a dispatch is `Idle` on success and `Failed` on error. `dispatch_with_running_hook` calls a closure with the `Running` state before the strategy starts.
- `stop()` deactivates and stops every agent, clears the pool and bus, and resets status to `Idle` with `messages` cleared.
- `get_state()` refreshes token usage and message history from live agents before returning.

`SwarmStatus` is `Idle`, `Running`, `Completed`, `Failed`. `SwarmState` carries `id`, `status`, `agent_ids`, `messages`, `results`, `token_usage`, `started_at` and `completed_at`.

### Agent factory and hooks

The factory receives a `CoordinatorAgentFactoryContext`: the config, swarm id, agent id and closures `send`, `broadcast`, `inbox`, `participants`, optional `delegate_task` / `delegate_tasks` (manager only) and `check_budget`. It returns a `CoordinatorAgentShell` (`run`, `token_usage`, `clear_task_state`, `stop`). A strategy gets a `CoordinatorDispatchContext` with the task, manager and worker configs, the limits, the bus, and `spawn_agent` / `spawn_manager`.

The daemon provides the factory (`hosts/rust-daemon/src/state/swarm_runtime.rs`): each agent is an `AgentRuntime` with swarm tools `send_message`, `broadcast_message`, and for managers `delegate_task`, `delegate_tasks` or `choose_speaker` (`state/swarm_tools.rs`). `core_memory` is refused inside swarms.

A custom strategy is a `CoordinatorStrategyFn`: a function from `CoordinatorDispatchContext` to a boxed future of `TaskResult<Content>`. Pass it to `with_hooks`.

## Lifecycle at a Glance

```
start()           workers spawned through the factory and pooled
dispatch(task)    strategy runs: spawn manager / reuse pooled workers → results → state updated
                  non-pooled agents (the manager) are stopped
stop()            everything stopped, bus cleared
```

## Related Types

`SwarmAgentHandle`, `SwarmAgentRunFn`, `SwarmFuture`, `StrategyContext`, `StrategyFn` and the `SwarmMessageBus` trait are re-exported from `types.rs`. The `Coordinator*` types (`CoordinatorDispatchContext`, `CoordinatorAgentFactoryFn`, `CoordinatorStrategyFn`, ...) in `coordinator.rs` are what the coordinator actually uses; reach them through `anima_swarm::coordinator`.
