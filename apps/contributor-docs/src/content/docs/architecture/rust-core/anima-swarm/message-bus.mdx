---
title: Message Bus
description: The in-memory inbox and history store between swarm agents
---

`MessageBus` is an in-memory store of per-agent inboxes plus a global history. It is not a pub/sub transport: the daemon publishes live events through its own hooks.

```rust
pub struct MessageBus {
    inboxes: HashMap<String, Vec<AgentMessage>>,
    all_messages: Vec<AgentMessage>,
}
```

The `SwarmMessageBus` trait (`send`, `broadcast`, `get_messages`, `get_all_messages`, `clear`, `clear_inboxes`) is what strategies see; `MessageBus` implements it.

## Operations

| Method | Description |
|--------|-------------|
| `register_agent(id)` / `unregister_agent(id)` | Create or remove an agent's inbox |
| `send_message(from, to, content)` | Append to the history and, if `to` has an inbox, to it. Returns the `AgentMessage`. |
| `broadcast_message(from, content)` | Append to the history with `to = "broadcast"` and to every inbox except the sender's |
| `get_messages(id)` | Clone one agent's inbox |
| `get_all_messages()` | Clone the global history |
| `clear()` | Drop all inboxes and the history |
| `clear_inboxes()` | Empty inboxes, keep registrations and the history |

(`send` and `broadcast` are the trait-style forms that discard the returned message.)

## AgentMessage

```rust
pub struct AgentMessage {
    pub id: String,        // "swarm-msg-<millis>-<n>"
    pub from: String,
    pub to: String,        // an agent id, or "broadcast"
    pub content: Content,
    pub timestamp: u64,    // ms since the UNIX epoch
}
```

## How the Coordinator Uses It

Each agent shell gets `send`, `broadcast`, `inbox` and `participants` closures from the coordinator. The send and broadcast closures check the sender is still live, write to the bus, then call the optional `CoordinatorMessageEventFn` (swarm id plus the message). `get_state()` and the end of every dispatch copy `get_all_messages()` into `SwarmState.messages`. `stop()` clears the bus and `SwarmState.messages`.

## Boundaries

- No size cap or eviction: inboxes and history grow for the life of a live coordinator.
- Inboxes are coordinator memory. A daemon restart restores the registered swarm and its last `SwarmState` (including `messages`) from the control plane, but not live inboxes, and it never resumes a partly finished dispatch.
- Time limits are not enforced here. The daemon's route layer applies the run request timeout, and `token_budget` is checked by host hooks.

## Daemon Events

`MessageBus` emits nothing itself. The daemon wires `CoordinatorMessageEventFn` to publish `swarm:message` on the swarm event streams and to persist message relationships into memory. The swarm SSE stream (`GET /api/swarms/{swarm_id}/events`) uses these event names:

| Event | When |
|-------|------|
| `swarm:created` | A swarm is registered |
| `swarm:running` | A dispatch starts running |
| `swarm:message` | A message is sent or broadcast: `{ swarmId, message }` |
| `swarm:completed` | A dispatch finishes; payload `{ swarmId, state, result }` |
| `swarm:lagged` | The subscriber fell behind: `{ missed }` (refetch the swarm state) |
| `task:started`, `task:completed`, `task:failed`, `tool:before`, `tool:after`, `agent:tokens`, `agent:terminated` | Republished runtime events of the swarm's agents |
