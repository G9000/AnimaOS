## Problem

Agent tooling tends to lock you in at one of two layers:

- **Frameworks** own your abstractions. When they change, you rewrite.
- **Platforms** own your runtime and your data. When they break, you are down.

## Solution

Separate **engine** from **host**.

The engine (`packages/core-rust`) defines behavior: the agent loop, memory search, swarm coordination, model-provider adapters. `anima-core` has no HTTP, database or filesystem code; everything it needs from the outside arrives through traits. A host wraps the engine and provides reality: the HTTP server, persistence, credentials, connectors, process control.

Today there is one host, `hosts/rust-daemon`, and the SDK, CLI, TUI and web console are thin clients of it. The boundary is the daemon's HTTP/SSE contract, so a client never embeds an engine.

## Memory-First

Memory is a primitive of the runtime, not a bolt-on. Recall fuses lexical (BM25), vector, relationship, temporal and recency signals. Each agent also has small always-on **core memory** blocks the owner can read and edit, and the daemon reviews conversations to propose edits. See [anima-memory](/architecture/rust-core/anima-memory/).

## The Owner Stays in Control

The daemon assumes one trusted owner on a local machine and an agent that must earn each risky action:

- Every tool is risk-classed (read, write, exec, network, delegate) and judged against a per-agent policy, rules and session allowances. Calls that need the owner wait for an explicit decision.
- Owner-only routes require a loopback bind and either an approved browser origin or an admin token. Credentials live in the OS credential store, not in files or in model-visible context.
- Interrupted work is reported as interrupted. The daemon does not silently replay uncertain effects.

See [Runs and Sessions](/hosts/rust-daemon/runs/).

## Swarms

A single agent is bounded by one model's context window. `anima-swarm` coordinates a manager and workers with three strategies (supervisor, round-robin, dynamic) over an in-memory message bus.

## Rust + TypeScript

- **Rust** runs the engine and the host: memory-safe, no garbage collector, one deployable binary.
- **TypeScript** runs the surfaces (SDK, CLI, TUI, web console) where iteration speed and the React ecosystem matter.

## What animaOS Is Not

- Not a framework. You own your code.
- Not a hosted platform. You run the daemon.
- Not a model. Agents use the providers you configure.

## In One Sentence

animaOS is an engine and a local host for autonomous agents with long-term memory and swarm coordination, under the owner's control of the runtime and the data.
