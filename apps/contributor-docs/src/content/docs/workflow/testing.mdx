Run commands from the repo root. Prefer the Nx targets; they run the same cargo and vitest commands CI uses. `AGENTS.md` lists the required verification per area, and a change is not done until those commands pass in the current tree. Prefix with `NX_TUI=false` for quieter output, and add `--skipNxCache` when you need a real re-run.

Rust outputs share `target/cargo`. Run `bun run rust:cache:status` to check the cache; it warns above 64 GiB. Run `bun run rust:cache:clean` to remove only Cargo outputs, preserving files outside that directory.

## What to Run

| You changed | Command |
|-------------|---------|
| Rust host or core crates | `bun x nx run rust-daemon:test --skipNxCache` |
| Core crates only | `bun x nx run core-rust:test --skipNxCache` |
| Packaged program (`hosts/anima`) | `bun x nx run anima:test` |
| Dev launcher | `bun x nx test workspace-dev --runInBand --skipNxCache` |
| A TypeScript package | `bun x nx test <project>` plus `typecheck` and `build` |
| Public docs | `bun x nx run @animaos/docs:build --skipNxCache` |
| Contributor docs | `bun x nx run @animaos/contributor-docs:build --skipNxCache` |

## Rust Core

```bash
# All eleven core crates (Cargo outputs are in target/cargo)
bun x nx run core-rust:test

# One crate, or one module
cargo test -p anima-core
cargo test -p anima-memory memory_manager::tests
cargo test -p anima-swarm

# nextest, if installed
cargo nextest run -p anima-memory

# Everything in the Cargo workspace, daemon and packaged program included
cargo test --workspace
```

`core-rust:test` covers `anima-core`, `anima-service-adapters`, `anima-model-adapters`, `anima-memory`, `anima-schedule`, `anima-swarm`, `anima-harness`, `anima-document-content`, `anima-process`, `anima-acp` and `anima-worktree`. Some crates have integration tests under `tests/` (for example `anima-harness/tests/harness.rs`, `anima-model-adapters/tests/durable_engine_provider_loop.rs`) and `anima-acp` builds a fake ACP agent binary for its tests.

### Memory evaluation

```bash
# Fast deterministic regression gate (baseline_memory_eval_cases_pass)
NX_TUI=false bun x nx run core-rust:memory-eval --skipNxCache

# Temporal fact and relationship CRUD and supersession
cargo test -p anima-memory temporal -- --nocapture

# LoCoMo-style smoke benchmark (feature "locomo-eval")
NX_TUI=false bun x nx run core-rust:memory-locomo --skipNxCache

# Download the public dataset into .cache/locomo (git-ignored), then run the full retrieval benchmark
NX_TUI=false bun x nx run core-rust:memory-locomo-fetch --skipNxCache
NX_TUI=false bun x nx run core-rust:memory-locomo-dataset --skipNxCache

# End-to-end agent benchmark with real model calls (expensive; needs real provider config)
NX_TUI=false bun x nx run rust-daemon:memory-locomo-agent --skipNxCache
```

Thresholds and tunables (`LOCOMO_*` variables, `ANIMAOS_RS_MEMORY_QUERY_EXPANDER=locomo`) are documented in `docs/testing.md`. The dataset targets compile `anima-memory` with `locomo-eval`. The agent benchmark fails without real providers; it never falls back to the deterministic model. A no-default-features portability check: `CARGO_TARGET_DIR=target/cargo/validation-memory-no-default cargo test -p anima-memory --no-default-features`.

### Node oracles and the browser worker

`core-rust` also has Node-based targets that run `node --test`: `browser-worker-test` (the Playwright worker in `browser-worker/`), `coding-acceptance-test` (`acceptance/coding-m47`), `coding-acceptance-m87-test`, `coding-reliability-test` (`coding-m86`), `provider-task-acceptance-test` (`provider-task-m52`) and `research-acceptance-test` (`research-m84`). They are not cached and not parallel.

### Mocking in Rust tests

The core uses traits for every external dependency, so tests inject fakes. A model adapter only needs `provider` and `generate`; `stream` falls back to `generate`:

```rust
struct Scripted(ModelGenerateResponse);

#[async_trait]
impl ModelAdapter for Scripted {
    fn provider(&self) -> &str { "scripted" }
    async fn generate(&self, _c: &AgentConfig, _r: &ModelGenerateRequest)
        -> Result<ModelGenerateResponse, String> {
        Ok(self.0.clone())
    }
}

#[tokio::test]
async fn run_succeeds() {
    let mut runtime = AgentRuntime::new(config(), Arc::new(Scripted(end_response("hi"))));
    let result = runtime.run(Content { text: "hello".into(), ..Content::default() }).await;
    assert_eq!(result.status, TaskStatus::Success);
}
```

For provider HTTP code, `anima-model-adapters` tests run local `axum` servers. For the daemon, use the in-process router constructors (`app_with_config` and friends use a deterministic model adapter).

## Rust Daemon

```bash
# Standard run: core-rust:test first, then cargo test -p anima-daemon
bun x nx run rust-daemon:test --skipNxCache

# Format check
bun x nx run rust-daemon:lint --skipNxCache

# Windows, when a running daemon locks target/cargo/debug/anima-daemon.exe
CI=1 CARGO_TARGET_DIR=target/cargo/validation-rust-daemon bun x nx run rust-daemon:test --skipNxCache
```

<Aside type="note">
The Windows workaround uses a separate target directory so the running binary and the test binary do not conflict. In PowerShell set `$env:CI="1"` and `$env:CARGO_TARGET_DIR="target/cargo/validation-rust-daemon"` first (and clear them afterwards).
</Aside>

Daemon tests live in `hosts/rust-daemon/tests/` (HTTP-level: `agent_api`, `connector_api`, `memory_api`, `schedule_api`, `swarm_api`, `workspace_api`, `health`, `document_worker`, `step_log_integration`) and in `*_tests.rs` files beside the modules. They build routers in process, use deterministic model adapters, fake connector transports and credential stores, temporary stores and random ports, and never call real providers, open real accounts or start containers. Connector tests follow `CONNECTOR-CONTRIBUTING.md`: injected fakes and deterministic barriers, no real services, no reading user profiles or secrets. `step_log_integration` is `#[ignore]`d because it needs a `DATABASE_URL`-backed Postgres; run it deliberately with `cargo test -p anima-daemon --test step_log_integration -- --ignored`.

## TypeScript Packages

```bash
bun x nx test @animaos/sdk
bun x nx test @animaos/tui
bun x nx test @animaos/cli
bun x nx test @animaos/web
bun x nx typecheck @animaos/sdk

# Everything
bun run test
bun run typecheck
```

Tests use Vitest. Each project has a `vitest.config.mts`; `vitest.workspace.ts` collects them. Mock `fetch` for SDK and CLI tests; the SDK's `*.spec.ts` files next to each module are the model to follow. When you change a daemon route or response shape, update the matching SDK module and spec.

The TUI exports `EventBus` and the `IEventBus` interface (`on`, `emit`, `clear`), so components and hooks take a mock:

```typescript
import { vi } from 'vitest';
import type { IEventBus } from '@animaos/tui';

const bus: IEventBus = {
  on: vi.fn(() => () => {}),
  emit: vi.fn().mockResolvedValue(undefined),
  clear: vi.fn(),
};
```

## Browser Journeys

`apps/web-e2e` covers the console with Playwright. The offline journeys need no daemon, dev server or database: fake APIs fulfill routes and real SSE bytes go through the SDK parser.

```bash
bun x nx run @animaos/web-e2e:e2e-console --skipNxCache
bun x nx run @animaos/web-e2e:typecheck --skipNxCache
bun x nx run @animaos/web-e2e:deployment-contracts --skipNxCache
```

CI runs `e2e-ci` through `nx run-many`. The service-starting suites (`e2e`, companion configuration) use preview and dev servers and are kept for separately authorized runtime testing. Simulated passes do not establish real HTTP chunking, selected-model streaming, microphone behavior or container restarts; see `deploy/vps/README.md` for manual acceptance.

## Dev Launcher

```bash
bun x nx test workspace-dev --runInBand --skipNxCache
```

These tests cover host selection and argument parsing, the persistence environment for the dev daemon, process orchestration and graceful shutdown, and the daemon build and signing arguments (`hosts.spec.ts`, `main.spec.ts`, `process.spec.ts`, `rust-daemon-dev.spec.ts`).

## Diff Hygiene

```bash
git --no-pager diff --check
```

On Windows this can print LF-to-CRLF warnings; conflict markers and trailing-whitespace errors are the blocking problems. Git Bash accepts inline `NX_TUI=false command`; in PowerShell set `$env:NX_TUI="false"` first.

## Continuous Integration

`.github/workflows/ci.yml` runs on pushes to `main` and on pull requests:

1. `bun install --frozen-lockfile`
2. `nx format:check --base=remotes/origin/main`
3. `bun x nx run-many -t lint test build typecheck e2e-ci`

Nx Cloud distributes the work. The Rust targets (`core-rust`, `rust-daemon`, `anima`) are part of `run-many`. Releases have their own workflows (`release.yml`, `sign-release.yml`).

## Golden Rules

1. **Never call real LLM APIs or real services in tests.** Inject a mock `ModelAdapter` or transport.
2. **Never read or write a user's real stores or credentials.** Use temporary directories and in-memory credential stores.
3. **Deterministic tests.** No random seeds, no wall-clock-dependent assertions; use deterministic barriers and manual clocks.
4. **Add tests for meaningful behavior and regression risks**, not for trivial edits.
5. **Fast feedback.** Run the smallest target that covers your change, then the full target before pushing.
