## Prerequisites

- [Bun](https://bun.sh) (the repo pins `bun@1.3.8` in `package.json`; CI uses the same)
- [Rust](https://rustup.rs) (stable)
- [cargo-nextest](https://nexte.st) (optional)
- [Git](https://git-scm.com)

## First Setup

<Steps>

1. Clone the repo

   ```bash
   git clone https://github.com/G9000/animaos.git
   cd animaos
   ```

2. Install JavaScript dependencies

   ```bash
   bun install
   ```

3. Verify the Rust toolchain

   ```bash
   cargo --version
   rustc --version
   ```

4. Install cargo-nextest (optional)

   ```bash
   cargo install cargo-nextest --locked
   ```

</Steps>

## Running the Dev Environment

`bun dev` runs the `workspace-dev` launcher directly. The launcher (`tools/workspace-dev`) starts the selected host plus the browser and docs surfaces. The only host key is `rust`, and it is the default, so `bun dev` and `bun dev --host rust` are the same.

```bash
# Rust daemon + web console + playground + public docs + contributor docs
bun dev --host rust

# Only the Rust daemon (build, optional macOS re-sign, run)
bun run --filter rust-daemon dev      # same as: bun run daemon

# One surface at a time
bun run --filter @animaos/web dev
bun run --filter @animaos/playground dev
bun run --filter @animaos/docs dev
bun run --filter @animaos/contributor-docs dev
```

If a daemon already answers on `http://127.0.0.1:8080/api/health`, `bun dev` reuses it and starts only the other four processes. An unknown host key (`--host elixir`, `--host python`) fails with `Unknown host`: those placeholders were removed.

### Dev Data Persists

The daemon `bun dev` starts is given `ANIMAOS_RS_CONTROL_PLANE_FILE=~/.animaos-swarm/data/control-plane.json`, so agents, connectors, history and memory survive restarts (`history.sqlite` and `memory.sqlite` sit beside it). Your own control-plane path or Postgres mode wins, and `ANIMAOS_DEV_EPHEMERAL=1` opts out. This folder is the same one an installed `anima` uses; see [Persistence](/hosts/rust-daemon/persistence/#development-defaults).

### Port Map

| Service          | Port   | Notes                                                           |
| ---------------- | ------ | --------------------------------------------------------------- |
| Rust daemon      | `8080` | HTTP API and SSE (`bun dev`). The installed `anima` uses `8787` |
| Web console      | `4200` | Vite; proxies the daemon (`UI_BACKEND_ORIGIN`)                  |
| Playground       | `4201` | Vite                                                            |
| Public docs      | `4321` | Astro default                                                   |
| Contributor docs | `4322` | This site (`server.port` in `astro.config.mjs`)                 |

The daemon treats `http://localhost:4200`, `http://127.0.0.1:4200`, `4201` as the browser origins allowed to act as the local owner; change them with `ANIMA_ALLOWED_UI_ORIGINS`.

## IDE Setup

The repo recommends (in `.vscode/extensions.json`) the Prettier and Playwright extensions. For Rust add `rust-lang.rust-analyzer`; for docs, `astro-build.astro-vscode`.

rust-analyzer needs no configuration: the Cargo workspace is the root `Cargo.toml`, and it discovers every crate and both hosts. There is no `packages/core-rust/Cargo.toml`.

## Workspace Commands

Use `bun run --filter <workspace-name> <script>` for focused work. Inspect the workspace's `package.json` before assuming a script or its arguments; use the underlying tool's `--help` when needed.

### Rust

```bash
# Daemon: build (debug), test (runs core-rust:test first), format check
bun run --filter rust-daemon build
bun run --filter rust-daemon test
bun run --filter rust-daemon lint

# Core crates only
bun run --filter core-rust test
bun run --filter core-rust lint

# Packaged program
bun run --filter anima test

# Plain cargo, one crate
cargo check -p anima-core
cargo test -p anima-memory
```

### TypeScript

```bash
bun run --filter @animaos/sdk build
bun run --filter @animaos/sdk test
bun run --filter @animaos/web typecheck
bun run --filter workspace-dev test

# Everything
bun run build
bun run test
bun run typecheck
bun run lint          # oxlint over packages/*/src and apps/*/src
```

### Docs

```bash
bun run --filter @animaos/docs build
bun run --filter @animaos/contributor-docs build
```

## Workspace Discovery

The root `package.json` lists workspace directories under `workspaces`. Each workspace's `package.json` declares its name, dependencies, and scripts. Use focused scripts for the area you changed, or the root commands above to check all workspaces.

## Adding a New Package

See [Monorepo Structure](/architecture/monorepo/#adding-a-new-package). TypeScript packages follow the existing `package.json` scripts plus `tsconfig.lib.json` pattern (see `packages/sdk`). Declare dependencies with `workspace:*` and run `bun install` to link them. Rust crates are Cargo workspace members and also need their `-p` entry in `packages/core-rust/package.json`.

## Git Workflow

- Branch from `main`; open an issue first for large changes.
- Run the verification commands for the area you changed before pushing (see [Testing](/workflow/testing/)).
- CI checks changed files with Prettier, then runs root `lint`, `test`, `build`, and `typecheck` scripts plus the web-e2e `e2e-ci` script. Use `bun x prettier --write <changed-files>` for formatting fixes on TypeScript and docs.

## Debugging

### Rust

```bash
RUST_LOG=debug bun run --filter rust-daemon dev
RUST_LOG=anima_daemon=debug,tower_http=debug cargo run -p anima-daemon

cargo build -p anima-daemon
rust-lldb target/cargo/debug/anima-daemon
```

The log tail is also served at `GET /api/logs` and in the console. See [Operations](/hosts/rust-daemon/ops/).

### TypeScript

Use the VS Code JavaScript debugger on Vite (`apps/web`, `apps/playground`) or attach to Vitest (`bun run --filter <project> test`). The CLI runs from its build: `bun run build:cli-sdk`, then `bun run animaos <command>` (a script for `node packages/cli/dist/index.js`).
