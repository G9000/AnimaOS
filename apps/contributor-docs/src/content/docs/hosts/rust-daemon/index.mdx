`anima-daemon` (`hosts/rust-daemon`) is the runnable host for animaOS. It is an Axum HTTP/SSE server that wires the reusable crates in `packages/core-rust` to real infrastructure: model providers, SQLite and optional Postgres persistence, the OS credential store, connectors (Telegram, Discord, Google Drive, Calendar, Gmail and Outlook), MCP servers, process control and a browser worker. It is also a library: `hosts/anima` embeds it and adds supervision.

The long-form reference is `hosts/rust-daemon/README.md` (route inventory, per-feature limits and rollback notes); the live contract is `GET /openapi.json` and the Scalar UI at `/docs`. This section explains how the pieces fit and where to change them.

## Architecture

```
┌────────────────────────────────────────────────────────────┐
│  Clients: web console, SDK, CLI, TUI, curl      (HTTP / SSE)│
├────────────────────────────────────────────────────────────┤
│  Axum router (routes/)                                      │
│   request id, tracing, per-route timeouts, optional API key │
│   owner authorization (loopback bind + Origin or admin token)│
├────────────────────────────────────────────────────────────┤
│  Host services                                              │
│   AgentRunCoordinator   run ledger, queue, steer, stop      │
│   ApprovalRegistry      per-tool risk class, rules          │
│   JobService, SchedulerService   jobs, goals, automations   │
│   ConnectorManager, DiscordManager, DriveManager, ...       │
│   History worker        outbox flush, hot-tail pruning      │
│   MCP manager, browser service, process custody, ACP        │
├────────────────────────────────────────────────────────────┤
│  State: DaemonState behind Arc<RwLock<..>>                  │
│   agents, swarms, sessions, runs, approvals, memory + embeddings│
├────────────────────────────────────────────────────────────┤
│  anima-core · anima-memory · anima-swarm · anima-model-adapters │
│  anima-service-adapters · anima-document-content · anima-process│
│  anima-acp · anima-worktree                                 │
└────────────────────────────────────────────────────────────┘
```

The daemon implements `ModelAdapter` as `RuntimeModelAdapter` (provider routing over `anima-model-adapters`, fed by a key pool) and `DatabaseAdapter` as `SqlxPostgresAdapter` (Postgres step log). Each session run gets an adapter stack: `FallbackModelAdapter` (per-agent fallback models) over `AttachmentModelAdapter` (request-only attachment hydration) over the shared `RuntimeModelAdapter`.

## Startup Sequence

`run_from_env` then `serve_with`:

1. Validate `ANIMAOS_RS_KEYCHAIN_NAMESPACE`, initialize `tracing` (redacted in-memory log tail plus console), read `ANIMAOS_RS_HOST` / `ANIMAOS_RS_PORT`, parse the `ANIMAOS_RS_*` limits (`config_from_env`; invalid values fail startup), bind the listener and log `anima-daemon listening`.
2. Install the external memory provider (`ANIMAOS_RS_MEMORY_PROVIDER`; an unknown id stops boot), validate the Python tool bridge path (`ANIMAOS_RS_TOOL_RPC_PYTHON_PATH`), the checkpoint root (`ANIMAOS_RS_CHECKPOINT_ROOT`; absolute, and Windows only) and the browser config (`ANIMAOS_RS_BROWSER_CONFIG_FILE`).
3. Create ChatGPT auth, open the provider key pool, build `RuntimeModelAdapter` from the environment.
4. `configure_persistence`: connect to Postgres and run migrations when `ANIMAOS_RS_PERSISTENCE_MODE=postgres` (failure stops boot); choose and load the memory store; configure embeddings; load the control-plane store, upgrading it with a backup if needed; choose and open the history store; rewrite the core-memory file copies. See [Persistence](/hosts/rust-daemon/persistence/).
5. Start the background embedding model load (served daemon only).
6. Build the runtime services and router, then start restored workers in this order: job recovery, Telegram connectors, Discord connectors, Drive, the scheduler, and the skills scanner (rescans at startup and every 60 seconds). A background sweep removes stale clean helper worktrees.
7. Serve until Ctrl+C, SIGTERM or `POST /api/system/shutdown`.

## Request Boundary

Order of layers (`routes/mod.rs`): request id (`x-request-id` generated or propagated) and a tracing span per request; per-route-group timeouts; the optional API-key gate; cache protection on connector callback routes.

- **Timeouts.** Standard routes use `ANIMAOS_RS_REQUEST_TIMEOUT_SECS` (default 30). The blocking run routes (`/api/agents/{id}/run`, `/api/swarms/{id}/run`, `/api/agents/{id}/messages`, connector sends, `/api/agencies/generate`) use `ANIMAOS_RS_RUN_REQUEST_TIMEOUT_SECS` (default 600). Voice and speech routes have their own bounds. A timeout returns `408`; an admitted run keeps going.
- **Body limit.** `ANIMAOS_RS_MAX_REQUEST_BYTES` (default 64 KiB) is enforced by handlers through a bounded body reader, not by a global layer; some routes (uploads, skill import, session runs) apply their own larger limits.
- **API key.** If `ANIMAOS_RS_API_KEY` is set, every route except health, readiness, metrics, `/openapi.json`, `/docs` and the exact OAuth callback paths requires `Authorization: Bearer <key>` or `x-api-key`. Unset means trust-the-network, fine only for loopback.
- **Owner authorization.** Most routes that read or change a person's data are _owner-only_ (`LocalOwnerPolicy` in `routes/http.rs`). A request qualifies only if the daemon is bound to a loopback address, the `Host` header is loopback and no forwarding headers are present (`Forwarded`, `Via`, `X-Forwarded-*`, `X-Real-IP`, `Client-IP`, `True-Client-IP`, `CF-Connecting-IP`), and then one of: an `Origin` header that exactly matches an allowed browser origin (`http://localhost:4200`, `127.0.0.1:4200`, `4201`, plus `ANIMA_ALLOWED_UI_ORIGINS`; only the configured ones when `ANIMA_SUPERVISOR_URL` is set), or `Authorization: Bearer <ANIMA_LOCAL_ADMIN_TOKEN>` for originless clients. Read-only fetches may omit `Origin` when Fetch Metadata says `same-origin` and the referrer is an allowed origin. Lifecycle routes additionally need a console session. A non-loopback bind therefore makes owner-only routes answer `403`; this is deliberate and is why the VPS package keeps the daemon on loopback behind a gateway (see [Staging Deployment](/hosts/rust-daemon/staging/)).

## State and Concurrency

All mutable state lives in `DaemonState` behind one `Arc<RwLock<..>>` (`SharedDaemonState`). Services hold weak or shared references; locks are not held across network or persistence waits. Run admission is bounded by a semaphore (`ANIMAOS_RS_MAX_CONCURRENT_RUNS`, default 8) plus a per-agent limit (`ANIMAOS_RS_MAX_RUNS_PER_AGENT`, default 3, 1 to 64). Control-plane changes go through a single transaction mutex in `AgentRunCoordinator` so snapshots stay consistent.

## Graceful Shutdown

Ctrl+C or Unix SIGTERM (or the drain route's shutdown) starts a 40-second budget (`SHUTDOWN_BUDGET`). Producers close first: no new runs, jobs, schedule fires or connector admissions. Then admitted work drains (the run coordinator gives running runs up to 30 seconds to commit), connectors and the scheduler stop, the browser service closes, and the history worker does a final flush. Live SSE streams are closed first so open tabs never block exit. Work still unsettled when the budget expires is left for the next boot to mark `interrupted`, and a warning says admitted work may have uncertain effects. Memory snapshots are written as memory changes happen, not at shutdown.

## Rules for Contributors

- Reusable engine code belongs in `packages/core-rust`, not here.
- Do not add a tool without a risk class (see `approvals/policy.rs`).
- Never put secrets in the control plane, logs or model-visible text. Credentials go through the OS credential store (`keychain.rs`, `connectors/credentials.rs`).
- Every new owner route needs the owner-authorization check and `Cache-Control: no-store`, an entry in the OpenAPI registration and a handler test.
- For host changes run `bun run --filter rust-daemon test`.
