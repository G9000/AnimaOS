This site is for **contributors and maintainers** of animaOS. If you are looking for user-facing SDK, CLI, or TUI documentation, see the [public docs site](https://github.com/G9000/animaos/tree/main/apps/docs). The repository's `AGENTS.md` states the current repo rules and verification commands; this site expands on them.

## What is animaOS?

animaOS is an agent runtime with a Rust engine and a single runnable host:

1. **Core** (`packages/core-rust`): reusable Rust crates for the agent loop, memory, swarms, model-provider adapters and a few tool-support libraries. `anima-core` has no HTTP, database or filesystem dependency.
2. **Host** (`hosts/rust-daemon`): the `anima-daemon` process. It wraps the core in an Axum HTTP/SSE server and supplies the real world: provider calls, persistence, connectors, approvals, process custody.
3. **Packaged host** (`hosts/anima`): the installable `anima` program. It supervises the daemon, adds a tray icon and a self-updater, and embeds the web console.
4. **Surfaces**: the TypeScript SDK, CLI, TUI, web console and playground. They are thin clients of the daemon over HTTP/SSE and embed no execution engine.

The repo previously carried a TypeScript runtime, a mod system, an agency generator and placeholder Elixir/Python hosts. They were removed; the Rust daemon is the only host.

## Design Philosophy

- **Core defines behavior, hosts provide reality.** `anima-core` does no I/O. External concerns (model calls, storage, tools) arrive through traits such as `ModelAdapter`, `Provider`, `Evaluator` and `DatabaseAdapter`.
- **One host, thin clients.** The SDK, CLI, TUI, web console and playground talk to the daemon on `127.0.0.1:8080` (dev) or `8787` (installed). Host selection for dev lives in `tools/workspace-dev` only.
- **Memory is a first-class primitive.** Agents have BM25 plus vector plus relationship plus temporal recall, owner-editable core memory, and conversation reviews. See [anima-memory](/architecture/rust-core/anima-memory/).
- **The owner stays in control.** Tool calls are risk-classed and gated by per-agent approval policy; owner-only routes require a loopback bind and an approved browser origin or an admin token. See [Runs and Sessions](/hosts/rust-daemon/runs/).

## Key Rules

- **Do not move reusable code into `hosts/`.** If it could serve more than one host, it belongs in `packages/`.
- **Do not make `anima-core` depend on an HTTP framework, DB driver or host runtime.**
- **Keep host selection centralized** in `tools/workspace-dev`; do not hardcode host ports or project names in UI or client packages.
- **TypeScript surfaces are thin clients.** Behavior changes go in the daemon, not in the SDK or console.

## Getting Started

<Steps>

1. **Install prerequisites**

   - [Bun](https://bun.sh) (the repo pins `bun@1.3.8`)
   - [Rust](https://rustup.rs) (stable)
   - [cargo-nextest](https://nexte.st) (optional)

2. **Clone and install**

   ```bash
   git clone https://github.com/G9000/animaos.git
   cd animaos
   bun install
   ```

3. **Start the dev environment**

   ```bash
   bun dev --host rust
   ```

   This starts the Rust daemon on `127.0.0.1:8080`, the web console (`4200`), the playground (`4201`), the public docs (`4321`) and these contributor docs (`4322`). The daemon keeps its data across restarts; see [Development](/workflow/dev/).

4. **Run the checks for what you changed**

   ```bash
   # Rust host or core crates
   bun x nx run rust-daemon:test --skipNxCache

   # TypeScript packages
   bun x nx test @animaos/sdk
   ```

</Steps>

## Contribution Workflow

1. **Open an issue first** for large changes (new crates, breaking API changes).
2. **Branch from `main`.**
3. **Write tests** for meaningful behavior and regression risks.
4. **Run the verification commands** for the area you changed (see [Testing](/workflow/testing/)). Do not claim completion until they pass in the current tree.
5. **Update docs** when you change public APIs, routes, env vars or architecture.
6. **PR description** should reference the issue and explain the change.

## Code Review

CI (`.github/workflows/ci.yml`) runs `nx format:check` against `main`, then `bun x nx run-many -t lint test build typecheck e2e-ci`. For Rust changes, run `bun x nx run rust-daemon:test --skipNxCache` locally first. On Windows, if a running daemon locks the binary, use `CI=1 CARGO_TARGET_DIR=target/cargo/validation-rust-daemon bun x nx run rust-daemon:test --skipNxCache`.
