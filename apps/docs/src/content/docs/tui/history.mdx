`animaos launch` keeps a local record of the tasks it runs, so you can reopen a result, rerun a task or give a run a name after the session ends.

## Where History Lives

For a workspace launched with `animaos launch`, history is stored in `anima-history.json` next to `anima.yaml`. The newest 100 entries are kept. Each entry records the task, its result text, whether it failed, a timestamp and an optional label. Both TUI and `--no-tui` launches append to it.

When an interactive session starts and the file has entries, the TUI opens the most recent one as a resumed result.

<Aside type="note">
  History is local CLI state, not a daemon API. Conversation history on the daemon (sessions and messages) is separate; see [Sessions & Runs](/sdk/sessions/).
</Aside>

## Browsing

- `/history` opens the run browser with the newest run selected.
- `/resume` opens the browser for resuming: named runs first, then the rest newest first, with the first one selected.
- `/resume <label>` opens a run directly. Matching tries an exact label, then a prefix, then a substring. With several matches, the TUI shows up to three and you pick with Ctrl+N, Ctrl+P and Ctrl+Y; with none, it suggests the closest labels.
- Ctrl+O opens saved runs between tasks.

In the browser: `↑` and `↓` move, `/` searches task and result text (`n` and `N` jump between matches), Enter opens the selected run, `r` retries it, and `q`, `b` or Esc returns.

## Resumed Views

Opening a run shows its task and result. From there:

- `/back` returns to the swarm view.
- `/retry` reruns the task when the daemon is healthy. While the daemon is down it is unavailable, and `/health` rechecks.
- `/rename <label>` names the run so you can find it again with `/resume`.
- `/delete` removes it.

## Naming, Deleting and Undoing

Names are labels you set with `/rename`; a label already used by another run is refused, and the TUI suggests the next free one. In the resume browser, `x` deletes the selected run (press it again to confirm). From the input bar, `/delete <label>` needs an exact label and asks you to repeat the command; any other command cancels the pending delete.

Deleted runs go into an undo queue of up to five. `/undo` (or `u` in the resume browser) restores the most recent one, `/undo-status` shows the queue, and `/undo-drop` (or `D`, pressed twice) discards the oldest queued entry. The queue lives in memory for the session. After a delete or a rename the history file is rewritten.

`/clear` empties the session, the undo queue and the history file.

## Retrying

`/retry` reruns the open run's task, or the last task if none is open. A retry is a new run, so it adds a new entry rather than overwriting the old one.

## Suggested Workflow

1. Launch a workspace with `animaos launch`.
2. Run a few tasks.
3. Use `/history` to inspect earlier runs, and `/rename` to name the ones worth keeping.
4. Next session, use `/resume <label>` and `/retry` to continue.
