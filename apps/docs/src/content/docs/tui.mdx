The animaOS terminal UI is built with [Ink](https://github.com/vadimdemedes/ink) and runs in your terminal. It is a client of the Rust daemon: `animaos launch` creates a swarm from your `anima.yaml` on the daemon, subscribes to its event stream, and draws the agents, messages, tool calls and results as they arrive. It is not the main surface for everyday use of anima (that is the web console); it is a lightweight way to run and watch an agent team from a workspace.

<Aside type="caution">
  The TUI sits behind `animaos launch`. `animaos run` and `animaos chat` are plain text and never render it, and `animaos launch --no-tui` is the plain-text mode.
</Aside>

## Recommended Flow

1. Start the daemon.

   ```bash
   bun run daemon
   ```

2. Create a workspace, or write an `anima.yaml` by hand for a team.

   ```bash
   animaos create agent content-writer -d "Research topics and write articles"
   ```

3. Launch it in the TUI.

   ```bash
   cd content-writer
   animaos launch
   ```

## Launch Modes

```bash
animaos launch                       # interactive TUI session
animaos launch "Build a website"     # one task in the TUI, then exit
animaos launch --no-tui "Build a website"   # plain text, for scripts and CI
```

- **Interactive** (no task) opens an input bar. Each task you enter runs on the swarm, and past runs stay available. If the workspace has saved history, the last run opens first as a resumed result.
- **One task** runs it, shows the live view, and exits when you press Enter, Esc or `q`. While it is on screen, `t` opens the trace, `h` the history and `r` reruns the task.

`launch` seeds daemon memories from `agents/<slug>/memory/seed.json`, saves run history in the workspace, and in the TUI writes the latest task and result to `anima-result.md`.

## What You See

The live swarm view stacks these panels:

| Panel | Description |
|-------|-------------|
| **Header** | Strategy, agent count (and how many are active) and the current task |
| **Agents** | The configured agents plus any live ones, with status (`idle`, `thinking`, `running_tool`, `done`, `error`) and tokens |
| **Messages** | The latest agent-to-agent and lifecycle messages |
| **Tools** | The latest tool calls with status, truncated arguments and duration |
| **Past runs** | In interactive mode, the three most recent saved runs |
| **Status bar** | Total tokens, elapsed seconds, agent count, `gaps` when events were missed, and `daemon: up` or `daemon: down` with the last check time |
| **Input bar** | In interactive mode, where you type tasks and slash commands |

Other full-screen views open from commands: the saved-run **History** and **Resume** browser, the **Trace** of messages and tool activity, a single **Result**, and the **Agents** editor.

## Operator States

- **Preflight check.** `launch` checks `GET /health` before the TUI starts and shows a warning if the daemon is unreachable.
- **Health polling.** While the TUI is open it rechecks the daemon about every 5 seconds.
- **Command-only mode.** When the daemon is down, the input bar blocks tasks (`daemon down - tasks paused; use /health or /help`) but still accepts commands such as `/health`, `/help`, `/history` and `/trace`.
- **Recovery.** When the daemon returns, a recovery notice appears and tasks work again.
- **Gaps.** If the daemon reports that your event stream fell behind (`swarm:lagged`), the status bar shows a `gaps` count so you know the trace has holes.

## Live Telemetry

The TUI subscribes to the swarm's SSE stream: task starts and completions, tool calls with arguments and results, per-agent token usage, and the final result. The same stream is available to your own code through the [SDK](/sdk/swarms/events/).

## Editing Agents

`/agents` opens the agent profiles from `anima.yaml`. Select an agent to view its profile; press `e` to edit `bio`, `lore`, `adjectives`, `topics`, `knowledge`, `style` and `system`, and Ctrl+S to save. Saving writes `anima.yaml` and makes the next task build a fresh swarm. Because `anima.yaml` is rewritten from the fields `launch` reads, fields it ignores (such as `mission` and `values`) are dropped on save.

<Aside type="tip">
  The TUI works best in a terminal with true color and at least 80 columns by 24 rows. Set `NO_COLOR` to turn colors off.
</Aside>
