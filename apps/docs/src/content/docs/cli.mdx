`animaos` is a thin command-line client of the Rust daemon. It does two kinds of work:

- local scaffolding of a single-agent workspace with `create`
- daemon-backed execution with `launch`, `run`, `chat`, `agents` and `assistant`

The daemon does the thinking; the CLI creates agents or swarms over HTTP, sends a task and prints the result. Most day-to-day use of anima happens in the web console, so treat the CLI as the scripting and terminal surface.

## Mental Model

- `animaos create` scaffolds a local single-agent workspace (`anima.yaml` plus profile files). It does not need the daemon.
- `animaos launch` runs an `anima.yaml` workspace as a swarm on the daemon. With no `--no-tui` it opens the [TUI](/tui/).
- `animaos run` sends one task to a temporary agent or swarm and prints plain text.
- `animaos chat` opens a plain-text REPL with a new daemon agent.
- `animaos agents` lists and shows the agents the daemon holds.
- `animaos assistant` chats with an existing agent by name (see the caution below).

## Installation

`@animaOS-SWARM/cli` is a private workspace package; it is not published to npm. Build it from the repository and run it through the root script:

```bash
bun install --frozen-lockfile
bun run build:cli-sdk
bun run animaos --help
```

`bun run animaos` runs `node packages/cli/dist/index.js`, the package's `animaos` binary. Examples on this site write `animaos ...`; in the repository, use `bun run animaos ...`.

<Aside type="note">
  `create` is local. `launch`, `run`, `chat`, `agents` and `assistant` talk to the daemon over HTTP, so a daemon must be running first (`bun run daemon`, or the installed `anima` program). The CLI sends no credentials, so it works against a daemon that has no `ANIMAOS_RS_API_KEY` set.
</Aside>

## Fast Path

<Steps>

1. Start the daemon.

   ```bash
   bun run daemon
   ```

2. Scaffold an agent workspace.

   ```bash
   animaos create agent content-writer \
     -d "Research topics and write high-quality articles"
   ```

3. Launch that workspace in the TUI.

   ```bash
   cd content-writer
   animaos launch
   ```

</Steps>

## Command Guide

### `animaos create`

Scaffold a single-agent workspace directory. This is a local filesystem workflow.

```bash
# Interactive mode: prompts for the agent name and description
animaos create

# Single-agent workspace
animaos create agent medicine-helper \
  -d "Research medical literature and summarize risks clearly"
```

`create` makes no model call. It writes the workspace from a template and records the provider in `anima.yaml`: the one you pass with `-p`, otherwise the first remote provider that has credentials in your environment, otherwise `deterministic`. Multi-agent agencies are not generated; write `anima.yaml` by hand for those (see [Agency Workflow](/cli/workspaces/#animayaml)) and run them with `animaos launch`. `animaos create agency` is refused with that message.

| Flag | Default | Description |
|------|---------|-------------|
| `--kind` | | `agent`; equivalent to `animaos create agent ...` |
| `-p, --provider` | auto | Provider recorded in the workspace (see [Providers](/cli/providers/)); an unknown name is an error |
| `-m, --model` | `gpt-4o-mini` | Model recorded in the workspace |
| `-d, --description` | | What the agent should do (prompted when omitted) |
| `--system` | | Custom system prompt for the agent |
| `--api-key` | | API key, used only to detect which provider is configured |

The directory name is the agent name, lowercased and kebab-cased. It contains:

```text
medicine-helper/
├── anima.yaml        # config used by launch
├── org-chart.mmd     # Mermaid org chart
├── README.md         # mission, values, roster
└── agents/
    └── medicine-helper/
        ├── profile.md
        ├── assets/
        └── memory/
```

### `animaos launch`

Run a workspace's `anima.yaml` as a swarm on the daemon.

```bash
cd content-team

animaos launch                                    # TUI, interactive
animaos launch "Write an article about Rust macros"   # TUI, one task
animaos launch --no-tui "Write an article about Rust macros"   # plain text, one task
animaos launch --no-tui                           # plain-text prompt
```

| Flag | Default | Description |
|------|---------|-------------|
| `-d, --dir <dir>` | `.` | Directory containing `anima.yaml` |
| `--api-key <key>` | | API key for the agency's provider, for this run |
| `--no-tui` | | Plain text instead of the Ink TUI |

Without `anima.yaml` in the directory, `launch` fails with `No anima.yaml found ... Run "animaos create" first`. Before sending a task it checks `GET /health` and warns when the daemon is unreachable.

Plain-text interactive launch prompts with `task >` and supports:

| Input | Description |
|-------|-------------|
| `exit` (or an empty line) | Quit |
| `/help` | Show the commands |
| `/health` | Recheck daemon connectivity |

### `animaos run`

Run a temporary agent, or a temporary swarm with `-s`, for one task.

```bash
# Single agent
animaos run "Summarize the Rust book" -m gpt-4o-mini

# Swarm with a manager and one worker
animaos run "Build a landing page" -s supervisor -m gpt-4o
```

| Flag | Default | Description |
|------|---------|-------------|
| `-m, --model` | `gpt-4o-mini` | Model to use |
| `-p, --provider` | `openai` | Provider |
| `-n, --name` | `task-agent` | Agent name (single-agent mode) |
| `-s, --strategy` | | `supervisor`, `dynamic` or `round-robin`; switches to swarm mode |
| `--api-key` | | API key override |
| `--no-tui` | | Skips the "TUI not available" note; `run` is always plain text |

Output is the result, then `Duration: ...ms | Tokens: ...`. A failed task prints the error and exits with code 1. Each `run` registers a new agent (or swarm) in the daemon; it is not removed afterwards.

<Aside type="caution">
  `run` is always plain text. Without `--no-tui` it first prints a note that TUI mode is not available for daemon-backed runs, then continues in plain text; pass `--no-tui` to skip the note.
</Aside>

### `animaos chat`

```bash
animaos chat -m claude-sonnet-4-5 -p anthropic
```

Creates a daemon agent and opens a REPL with a `you >` prompt. Type `exit` (or an empty line) to quit. Options: `-p, --provider` (default `openai`), `-m, --model` (default `gpt-4o-mini`), `-n, --name` (default `task-agent`) and `--api-key`. Each message is a blocking `agents.run()` call, and the agent stays registered after you exit.

### `animaos agents`

```bash
animaos agents list                  # every agent the daemon holds
animaos agents show researcher       # by name or id
```

`list` prints each agent's name, id, status, model and message and event counts. `show` adds token usage and the last task's status.

### `animaos assistant`

```bash
animaos assistant                    # same as: animaos assistant chat
animaos assistant chat -n assistant --user-name "Sam"
```

`assistant chat` is a REPL against an agent that already exists on the daemon, found by name (`-n, --name`, default `assistant`). It sends your `userId` and `userName` in each message's metadata (`--user-id` and `--user-name`, falling back to `ANIMAOS_USER_ID`, `ANIMAOS_USER_NAME` and the operating-system user name).

<Aside type="caution">
  The command's error text and `animaos assistant inbox` refer to an assistant mode and an `/api/assistant/outbox` route that the current Rust daemon does not serve. Expect `inbox` to fail with an HTTP error. For ongoing conversations with your agents, use the web console or the [Sessions & Runs](/sdk/sessions/) API.
</Aside>

## Environment

| Variable | Description |
|----------|-------------|
| `ANIMA_DAEMON_URL` | Daemon base URL for every daemon-backed command. Default `http://127.0.0.1:8080`; an installed `anima` program serves on `http://127.0.0.1:8787` |
| Provider key and base-URL variables | Used to detect and forward credentials. See [Providers & Environment](/cli/providers/) |
| `ANIMAOS_USER_ID`, `ANIMAOS_USER_NAME` | Defaults for `assistant chat` |

The daemon has its own settings (port, workspace root, persistence) that the CLI does not read; see the [daemon README](https://github.com/G9000/animaOS-SWARM/blob/main/hosts/rust-daemon/README.md#environment-variables).

## Good Defaults

- Use `create` and `launch` for a durable, human-editable workspace and the TUI.
- Use `run` for a one-off answer.
- Use `chat` for a quick agent REPL without a workspace.
- Use `agents` to see what the daemon holds after runs and restarts.
