This page covers the workflow that starts on disk: scaffold an agent workspace (or hand-write an `anima.yaml`), edit it like project files, then launch a temporary agency from it on the daemon. Every agent in a workspace is an equal; a launch picks a lead for that one task, and the team is gone when the launch ends.

## Core Split

- `animaos create` is local. It writes files and does not need the daemon.
- `animaos launch` is daemon-backed. It reads `anima.yaml`, forms a temporary agency on the daemon (the lead you choose coordinates, the other agents are members), and runs tasks through it.

## Create a Workspace

```bash
# Interactive prompt for name and description
animaos create

# Single-agent workspace
animaos create agent medicine-helper \
  -d "Research medical literature and summarize risks clearly"
```

`create` makes no model call. See the [CLI overview](/cli/#animaos-create) for its flags. It only scaffolds a single agent; to add more agents, list them in `anima.yaml` yourself.

## Workspace Shape

```text
medicine-helper/
├── anima.yaml
├── README.md
└── agents/
    └── medicine-helper/
        ├── profile.md
        ├── assets/
        └── memory/
```

- `anima.yaml` is the runtime config `launch` reads.
- `agents/<slug>/profile.md` is a human-readable profile. The slug is the agent name lowercased and kebab-cased.
- `agents/<slug>/memory/seed.json` holds optional starting memories. Add it by hand; `create` does not generate it.
- `README.md` is generated documentation; `launch` does not read it.

## `anima.yaml`

```yaml
name: content-team
description: Researches topics and writes articles
model: gpt-4o-mini
provider: openai
agents:
  - name: editor
    bio: Senior editor who plans and reviews the work
    system: Plan the work, check it, and combine the results.
    tools: [memory_search, web_fetch]
  - name: researcher
    bio: Finds and checks facts
    system: Research the assigned topic and return concise findings.
    tools: [web_fetch, exa_search]
  - name: writer
    bio: Writes clear articles
    system: Turn findings into a polished article.
    model: gpt-4o
```

| Top-level key | Required | Default | Description |
|---------------|----------|---------|-------------|
| `name` | yes | | Workspace name |
| `agents` | yes | | The agents, all equals; at least one, each with `name` and `system` |
| `description` | no | empty | Free text |
| `model` | no | `gpt-4o` | Default model for every agent |
| `provider` | no | `openai` | Default provider (see [Providers](/cli/providers/)) |
| `mission`, `values` | no | | Shown in the generated README |

Each agent accepts `name`, `bio`, `system`, `lore`, `adjectives`, `topics`, `knowledge`, `style`, `model` (overrides the workspace model), `provider` (overrides the workspace provider) and `tools`. A missing `name` becomes `unnamed`; names matter because seed memories are matched to agents by name.

An old file with an `orchestrator` key and no `agents` is refused. There is no strategy in the file: how a team works is chosen per launch.

### Tools

`tools` lists daemon tool names. Launch always gives every agent `memory_search` and `recent_memories` plus the memory plugin, and adds any of these you name: `memory_add`, `web_fetch`, `exa_search`, `get_current_time`, `calculate`, `read_file`, `list_dir`, `glob`, `grep`, `write_file`, `edit_file`, `multi_edit`, `todo_write`, `todo_read`, `bash`, `bg_start`, `bg_output`, `bg_stop` and `bg_list` (`memory_recent` is accepted as an alias of `recent_memories`). Any other entry is ignored with a warning, so unknown names stay declarative. Naming a tool only requests it: the daemon's own checks and the tool's prerequisites (for example a configured workspace for file tools) still apply.

## Launch a Workspace

```bash
cd medicine-helper

animaos launch                          # TUI, interactive
animaos launch "Summarize the latest research"   # TUI, one task
animaos launch --no-tui "Summarize the latest research"   # plain text
```

```bash
animaos launch --lead researcher "Find three sources"          # researcher leads this task
animaos launch -s round-robin "Draft and review the intro"    # take turns instead
animaos launch --max-parallel 2 "Split the research"          # supervisor: two members at once
```

See the [CLI overview](/cli/#animaos-launch) for flags (`-d, --dir`, `--api-key`, `--no-tui`, `--lead`, `-s, --strategy`, `--max-parallel`).

How launch forms the temporary agency:

- `--lead` names the agent that coordinates this launch (default: the first agent in `anima.yaml`); every other agent joins as a member. The lead has no special standing outside this launch.
- `-s, --strategy` picks how the team works: `supervisor` (default; the lead hands out work), `dynamic` (the lead picks who speaks next) or `round-robin` (members take turns).
- Each agent's model is its own `model`, otherwise the workspace `model`; its provider is its own `provider`, otherwise the workspace `provider`.
- `--api-key` applies to the workspace provider only. Provider credentials are otherwise taken from your environment.
- The team is formed on the first task and reused for the session. After an error, or after you save an agent in the TUI, the next task forms a fresh one. Saving in the TUI writes the agent back to `anima.yaml`; the team itself is never saved.

<Aside type="tip">
  Use `launch` when you want several agents on one task, saved history or the TUI. Use [`run`](/cli/daemon/) for a one-off result without a workspace.
</Aside>

## Seed Memories

If an agent has `agents/<slug>/memory/seed.json`, `launch` posts those memories to the daemon after it forms the agency, so the agents start with a baseline. The file is a JSON array (or a single object) of entries:

```json
[
  { "type": "fact", "content": "The audience is senior engineers.", "importance": 0.9, "tags": ["audience"] },
  { "type": "observation", "content": "Past articles ran about 800 words." }
]
```

| Field | Required | Description |
|-------|----------|-------------|
| `type` | yes | `fact`, `observation`, `task_result` or `reflection` |
| `content` | yes | Non-empty text |
| `importance` | no | Number from 0 to 1 (default `0.5`) |
| `tags` | no | Array of strings |

Invalid files stop the launch with an error naming the agent and entry. Posting failures, or an agent name that is not in the swarm, are reported as warnings and never block the launch. On success the CLI prints `Seeded N memories from agents/<slug>/memory/seed.json`.

## Saved History

Every task `launch` runs (TUI or plain text) is appended to `anima-history.json` in the workspace directory, keeping the newest 100 entries. In the TUI the same file backs `/history` and `/resume`, and `/clear` empties it. TUI runs also write the latest task and result to `anima-result.md`. See [History & Resume](/tui/history/).
