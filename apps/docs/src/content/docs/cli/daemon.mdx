These commands talk to the Rust daemon instead of writing local workspace files. Start a daemon first: `bun run daemon` from the repository, or the installed `anima` program.

## Choose the Right Command

| Command | Use it when | Notes |
|---------|-------------|-------|
| `run` | You want one result now | Creates a temporary agent (or swarm with `-s`) and prints plain text |
| `chat` | You want an interactive REPL with one agent | Creates one daemon agent and keeps the conversation open |
| `agents` | You want to inspect what the daemon holds | Lists and shows registered agents |
| `assistant` | You want to chat with an existing agent by name | Sends your user id and name as metadata |

## `animaos run`

```bash
# Single agent
animaos run "Summarize the Rust book" -m gpt-4o-mini

# Swarm
animaos run "Build a landing page" -s supervisor -m gpt-4o
```

| Flag | Default | Description |
|------|---------|-------------|
| `-m, --model` | `gpt-4o-mini` | Model to use |
| `-p, --provider` | `openai` | Provider (see [Providers](/cli/providers/)) |
| `-n, --name` | `task-agent` | Agent name (single-agent mode) |
| `-s, --strategy` | | `supervisor`, `dynamic` or `round-robin` |
| `--api-key` | | API key override |
| `--no-tui` | | Skips the "TUI not available" note |

In single-agent mode `run` creates an agent with the system prompt `You are a helpful task agent. Use tools when needed. Be concise.` and runs your task. With `-s` it creates a swarm with a manager and one worker using the same model and provider, runs the task, and prints the swarm's result and token total. Credentials are forwarded with the request (`--api-key`, otherwise the provider's environment variables), so switching keys never needs a daemon restart.

The agent or swarm stays registered in the daemon after the command finishes. They appear in `animaos agents list`, and agents can be removed with the SDK's `client.agents.remove()`.

## `animaos chat`

```bash
animaos chat -m claude-sonnet-4-5 -p anthropic
```

`chat` creates a daemon agent and opens a terminal REPL at `you >`. Type `exit` or press Enter on an empty line to quit. Replies print as `agent > ...`; a failed run prints `[error] ...` and the prompt returns. Options match `run` except for `-s`: `-p`, `-m`, `-n` and `--api-key`.

## `animaos agents`

```bash
animaos agents list
animaos agents show researcher
```

`list` prints a count, then each agent's name, id, status, model and message and event counts, or `No daemon-backed agents are currently registered.` `show` accepts a name or an id and adds token usage and the last task status; an unknown name prints the available agents and exits with code 1. Use it to check daemon state after launches, retries or restarts.

## `animaos assistant`

```bash
animaos assistant chat --name assistant --user-id sam --user-name Sam
```

Looks up an agent with that exact name on the daemon (default `assistant`) and opens the same kind of REPL as `chat`, attaching `{ userId, userName }` metadata to each message. If no agent has that name it exits with an error.

<Aside type="caution">
  `animaos assistant inbox [--since <ms>] [--limit <n>]` requests `/api/assistant/outbox`, a route the current Rust daemon does not serve, and the not-found error text mentions `ANIMAOS_RS_ASSISTANT_ENABLED`, which the daemon no longer reads. Treat `inbox` as unavailable.
</Aside>

## Targeting a Different Daemon

The CLI defaults to `http://127.0.0.1:8080`. Point it elsewhere with `ANIMA_DAEMON_URL`:

```bash
# An installed `anima` program
ANIMA_DAEMON_URL=http://127.0.0.1:8787 animaos agents list

# Another local port or host
ANIMA_DAEMON_URL=http://127.0.0.1:8081 animaos agents list
```

The CLI sends no authorization headers. It cannot reach a daemon that sets `ANIMAOS_RS_API_KEY`, and it does not use the owner routes (sessions, approvals and so on). For those, use the [SDK](/sdk/client/#authentication) with a custom `fetch`.
