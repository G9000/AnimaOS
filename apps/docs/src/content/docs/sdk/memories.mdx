The daemon's memory system gives agents long-term recall. Memories are stored per agent, can be scoped to rooms, worlds or sessions, and are retrieved with keyword search or **hybrid recall**: BM25 text matching fused with vector similarity, relationships, temporal facts, recency and importance. Memory is persistent when you configure a memory store (`ANIMAOS_RS_MEMORY_SQLITE_FILE` or `ANIMAOS_RS_MEMORY_FILE`).

## In This Section

- [Search & Recall](/sdk/memories/recall/) covers keyword search, fused recall, result scoring and recent-memory reads.
- [Evaluation & Retention](/sdk/memories/operations/) covers evaluated writes, evidence tracing, retention, readiness, entities and relationships.
- [Core Memory & Export](/sdk/memories/core/) covers the always-on core blocks, owner edits, temporal facts and downloading memory.

## Create a Memory

```typescript
const memory = await client.memories.create({
  agentId: 'AGENT_ID',
  agentName: 'researcher',
  type: 'fact',
  content: 'Rust daemon memory endpoint created',
  importance: 0.8,
  tags: ['sdk', 'memory'],
  scope: 'shared',
  roomId: 'room-1',
  worldId: 'world-default',
});
```

### `CreateMemoryInput` fields

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `agentId` | `string` | yes | Owning agent identifier |
| `agentName` | `string` | yes | Agent name |
| `type` | `MemoryType` | yes | Memory category |
| `content` | `string` | yes | Memory text |
| `importance` | `number` | yes | Importance score, 0 to 1 |
| `tags` | `string[] \| null` | no | Optional tags |
| `scope` | `MemoryScope` | no | Visibility: `shared`, `private` or `room` |
| `roomId`, `worldId`, `sessionId` | `string` | no | Context the memory belongs to |

`create()` returns the stored `Memory`: `id`, `agentId`, `agentName`, `type`, `content`, `importance`, `createdAt`, optional `tags`, `scope` and optional `roomId`, `worldId`, `sessionId`.

### `MemoryType` values

`fact`, `observation`, `task_result` or `reflection`. The daemon rejects anything else (`type must be one of fact, observation, task_result, reflection`).

### `MemoryScope` values

| Value | Behavior |
|-------|----------|
| `shared` | Visible to all agents in the same context |
| `private` | Visible only to the owning agent |
| `room` | Visible to agents in the specified room |

<Aside type="note">
  Memories also come from the agent's own tools (`memory_add`, `core_memory`), from conversation and task reviews, and from these routes. There is no per-reply memory evaluator.
</Aside>

## Search Memories

`search()` is keyword search over memory text and filters. Each result is the memory itself with an added `score`: the fields are flat, with no nested `memory` object.

```typescript
const results = await client.memories.search('daemon memory', {
  agentName: 'researcher',
  type: 'fact',
  limit: 5,
  minImportance: 0.5,
});

for (const result of results) {
  console.log(`[${result.score.toFixed(3)}] ${result.content}`);
}
```

### `MemorySearchOptions`

| Field | Type | Description |
|-------|------|-------------|
| `agentId`, `agentName` | `string` | Filter by agent |
| `type` | `MemoryType` | Filter by memory type |
| `scope` | `MemoryScope` | Filter by visibility scope |
| `roomId`, `worldId`, `sessionId` | `string` | Filter by context |
| `limit` | `number` | Maximum results |
| `minImportance` | `number` | Minimum importance |

## Recent Memories

```typescript
const memories = await client.memories.recent({
  agentId: 'AGENT_ID',
  scope: 'shared',
  limit: 20,
});
```

`RecentMemoriesOptions` has the same filters as search except `type` and `minImportance`.

## Recall

**Recall** is the richer retrieval API. It returns `{ memory, score, ... }` results ranked by a fusion of:

- lexical matches (BM25)
- vector similarity (semantic embeddings)
- relationship proximity to an entity
- temporal relevance
- recency
- stored importance

```typescript
const results = await client.memories.recall('evidence probe', {
  entityId: 'user-1',
  agentId: 'AGENT_ID',
  temporalLimit: 7,
  limit: 3,
});

for (const r of results) {
  console.log(`score ${r.score.toFixed(3)}: ${r.memory.content}`);
  console.log(`  lexical ${r.lexicalScore.toFixed(3)} vector ${r.vectorScore.toFixed(3)}`);
  console.log(`  relationship ${r.relationshipScore.toFixed(3)} temporal ${r.temporalScore.toFixed(3)}`);
}
```

### `MemoryRecallOptions`

All `MemorySearchOptions` plus:

| Field | Type | Description |
|-------|------|-------------|
| `entityId` | `string` | Entity for relationship scoring |
| `recallAgentId` | `string` | Agent performing the recall |
| `lexicalLimit` | `number` | Max lexical candidates |
| `recentLimit` | `number` | Max recent candidates |
| `relationshipLimit` | `number` | Max relationship candidates |
| `temporalLimit` | `number` | Temporal window size |

### `MemoryRecallResult`

`memory` (the recalled `Memory`), `score` (fused), and the contributions `lexicalScore`, `vectorScore`, `relationshipScore`, `temporalScore`, `recencyScore`, `importanceScore`.

## Embeddings

The daemon embeds memories in the background. The default is `fastembed` (`intfloat/multilingual-e5-small`, run locally); it starts on hashed vectors, downloads and loads the model, then rebuilds vectors, with keyword search covering memories not yet rebuilt. Other modes (`local`, `ollama`, `openai`, `openai-compatible`, `disabled`) are set with `ANIMAOS_RS_MEMORY_EMBEDDINGS`. Check progress with `client.memories.readiness()` ([Evaluation & Retention](/sdk/memories/operations/#readiness)).
