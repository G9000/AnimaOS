An **agent** in animaOS is a persistent, LLM-backed runtime registered with the daemon: a configuration, state, a main conversation, memory and a set of tools. Agents run tasks individually or join a [swarm](/sdk/swarms/). The web console and the [Sessions & Runs](/sdk/sessions/) API talk to the same agents.

## In This Section

- [Lifecycle & Retry](/sdk/agents/lifecycle/) covers create, run, update, remove, inspect and safe retry keys.
- [Tools](/sdk/agents/tools/) covers registering daemon tools by name or descriptor.

## Agent Configuration

`AgentConfig` is what `client.agents.create()` accepts. The `agent()` helper only types it.

```typescript
import { agent } from '@animaOS-SWARM/sdk';

const config = agent({
  name: 'researcher',
  model: 'gpt-4o-mini',
  provider: 'openai',
  system: 'You are a research assistant. Provide concise, factual answers.',
  bio: 'An AI research assistant',
  lore: 'Created to help users find information quickly.',
  knowledge: ['machine learning', 'neural networks'],
  topics: ['AI', 'science'],
  adjectives: ['curious', 'precise'],
  style: 'Concise and technical',
  tools: ['memory_search'],
  settings: {
    temperature: 0.7,
    maxTokens: 2048,
    maxRetries: 3,
  },
});
```

### `AgentConfig` fields

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `name` | `string` | yes | Agent name; must not be empty |
| `model` | `string` | yes | Model identifier, for example `gpt-4o-mini` |
| `provider` | `string` | no | Provider id such as `openai`, `anthropic`, `google`, `ollama`, `openrouter` (see [Providers & Environment](/cli/providers/)). Omit to use the daemon default |
| `system` | `string` | no | System prompt |
| `bio`, `lore`, `style` | `string` | no | Character fields |
| `knowledge`, `topics`, `adjectives` | `string[]` | no | Character fields |
| `tools` | `AgentToolInput[]` | no | Daemon tool names or JSON descriptors (see [Tools](/sdk/agents/tools/)) |
| `plugins` | `DaemonPluginDescriptor[]` | no | Plugin descriptors (`name`, `description`) |
| `settings` | `AgentSettings` | no | Model parameters (below) |

### `AgentSettings`

| Field | Type | Description |
|-------|------|-------------|
| `temperature` | `number` | Sampling temperature |
| `maxTokens` | `number` | Maximum tokens per response |
| `timeoutMs` | `number` | Request timeout in milliseconds |
| `maxRetries` | `number` | Retry count on transient failures |
| `maxToolIterations` | `number` | Cap on tool-call rounds in one run (read by the daemon; not named in the SDK type, which has an index signature) |
| `[key: string]` | `unknown` | Other keys are kept by the daemon |

Extra keys the daemon recognizes include `apiKey` and `baseUrl` (a per-agent provider credential and endpoint; the CLI sets them), `contextBudgetTokens` and `autoCompact` for conversation context, and `completionReview`. See the daemon README for what each does.

## Create an Agent

```typescript
const snapshot = await client.agents.create(config);
console.log(snapshot.state.id);
```

`create()` returns an `AgentSnapshot`:

| Field | Type | Description |
|-------|------|-------------|
| `state` | `DaemonAgentState` | `id`, `name`, `status`, `config`, `createdAtMs`, `tokenUsage` |
| `messageCount` | `number` | Messages in the daemon's hot tail (recent history; older messages live in the history store and are read through [sessions](/sdk/sessions/)) |
| `messages` | `DaemonAgentMessage[]` | The hot-tail messages |
| `eventCount` | `number` | Events emitted |
| `lastTask` | `DaemonTaskResult \| null` | Result of the most recent task |

`state.config` is the daemon's normalized view (`DaemonAgentConfig`): optional fields are `null` when unset, `tools` are full descriptors, and `settings` carries `maxToolIterations` and an `additional` map.

## List and Read Agents

```typescript
const agents = await client.agents.list();          // full snapshots with messages
const summaries = await client.agents.listSummaries(); // same, without `messages`
const one = await client.agents.get('AGENT_ID');

for (const entry of summaries) {
  console.log(`${entry.state.id}: ${entry.state.name} (${entry.state.status})`);
}
```

### `AgentStatus`

| Value | Meaning |
|-------|---------|
| `idle` | Waiting for input |
| `running` | Currently processing a task |
| `completed` | Last task finished successfully |
| `failed` | Last task failed |
| `terminated` | Agent was stopped |

### `TokenUsage`

`promptTokens`, `completionTokens` and `totalTokens`, all numbers.

## Run an Agent

`run()` sends one `Content` message and blocks until the run finishes.

```typescript
const run = await client.agents.run('AGENT_ID', {
  text: 'Research the latest advances in quantum computing',
});

if (run.result.status === 'success') {
  console.log(run.result.data?.text);
} else {
  console.error('Run failed:', run.result.error);
}
```

`DaemonTaskResult` is `{ status: 'success' | 'error', data: DaemonContent | null, error: string | null, durationMs }`, and `DaemonContent` is `{ text, attachments: Attachment[] | null, metadata: Record<string, unknown> | null }`.

Pass a stable `roomId` to keep consecutive direct turns in one conversation:

```typescript
await client.agents.run('AGENT_ID', { text: 'Plan the release' }, { roomId: 'release-planning' });
await client.agents.run('AGENT_ID', { text: 'Expand the testing steps' }, { roomId: 'release-planning' });
```

### `Content`

```typescript
interface Content {
  text: string;
  attachments?: Attachment[];
  metadata?: Record<string, unknown>;
}

interface Attachment {
  type: 'file' | 'image' | 'url';
  name: string;
  data: string;
}
```

### `AgentRunResponse`

| Field | Type | Description |
|-------|------|-------------|
| `agent` | `AgentSnapshot` | Updated agent snapshot after the run |
| `result` | `DaemonTaskResult` | Task execution result |

<Aside type="note">
  `agents.run()` is the compatibility path. The daemon answers `408` after `ANIMAOS_RS_RUN_REQUEST_TIMEOUT_SECS` (600 seconds by default) while an admitted run keeps going. The web console instead sends messages to a session and follows `/events`; see [Sessions & Runs](/sdk/sessions/).
</Aside>

### Retrying a run safely

When the daemon has durable step logging (Postgres persistence), completed tool steps are reused on a retried run if you resend the same `retryKey` or `idempotencyKey` in `metadata`.

```typescript
await client.agents.run('AGENT_ID', {
  text: 'Research the latest advances in quantum computing',
  metadata: { retryKey: 'quantum-brief-2026-05-04' },
});
```

- Reuse only happens when you resend the same key; omit it or use a new value for a fresh request.
- This is tool-step reuse, not a resume of a run interrupted by a daemon restart.

## Update and Remove

```typescript
const updated = await client.agents.update('AGENT_ID', {
  model: 'gpt-4o',
  system: 'Be brief.',
  fallbacks: [{ provider: 'anthropic', model: 'claude-sonnet-4-5' }],
});

await client.agents.remove('AGENT_ID');
```

`AgentUpdateInput` accepts `name`, `model`, `provider`, `system`, `tools` and `fallbacks`; at least one field is required. An empty `provider` or `system` string restores the default, and `fallbacks: []` clears them. `fallbacks` are models tried in order when the primary fails before replying: at most three, none equal to the primary. `remove()` fails with `409` while one of the agent's runs is running.

## Peer Messages

```typescript
const reply = await client.agents.sendMessage('SENDER_ID', 'RECIPIENT_ID', 'Review the release plan');
console.log(reply.agent.state.id, reply.result.data?.text);
```

`sendMessage(senderId, toAgentId, message)` requests one bounded recipient run and returns the recipient's `{ agent, result }`. It does not start an automatic message loop.

## Recent Memories

```typescript
const memories = await client.agents.recentMemories('AGENT_ID', { limit: 10 });

for (const memory of memories) {
  console.log(`[${memory.importance}] ${memory.type}: ${memory.content}`);
}
```

`AgentMemory` carries `id`, `agentId`, `agentName`, `type`, `content`, `importance`, `createdAt`, optional `tags`, `scope` (`shared`, `private` or `room`) and optional `roomId`, `worldId` and `sessionId`.

## Tasks, Jobs and Schedules

The agents client also holds the agent's saved task list (`tasks()`, `updateTasks()`), background jobs (`jobs()`, `createJob()` and friends) and the older `schedules()` helpers. Jobs, goals and automations are covered in [Jobs & Automations](/sdk/automations/); `updateTasks()` needs the revision from your last read and answers `409` for a stale one.

## Avatars

`setAvatar(agentId, blob)` stores a PNG, JPEG or WebP image (up to 5 MiB) in the workspace; `removeAvatar(agentId)` deletes it.

## Full Example

```typescript
import { agent, createDaemonClient } from '@animaOS-SWARM/sdk';

const client = createDaemonClient();

const researcher = await client.agents.create(
  agent({
    name: 'deep-researcher',
    provider: 'openai',
    model: 'gpt-4o',
    system: 'You are a thorough research assistant. Use tools to verify facts.',
    tools: ['memory_search', 'web_fetch'],
    settings: { temperature: 0.3, maxTokens: 4096 },
  })
);

const run = await client.agents.run(researcher.state.id, {
  text: 'What are the latest breakthroughs in fusion energy?',
});

console.log(run.result.data?.text);
```
