A **swarm** is a manager plus workers that collaborate on a shared task. The daemon's swarm coordinator runs them according to a strategy and streams what happens over SSE. Swarms are what `animaos run -s ...` and `animaos launch` use under the hood.

## In This Section

- [Event Streaming](/sdk/swarms/events/) covers the SSE stream, event names, payload shapes, monitoring and cancellation.

## Swarm Configuration

Use the `swarm()` helper for typed autocompletion.

```typescript
import { agent, swarm, createDaemonClient } from '@animaOS-SWARM/sdk';

const client = createDaemonClient();

const contentTeam = await client.swarms.create(
  swarm({
    strategy: 'round-robin',
    maxTurns: 10,
    manager: agent({
      name: 'manager',
      provider: 'openai',
      model: 'gpt-4o',
      system: 'Break complex tasks into subtasks and synthesize the final answer.',
    }),
    workers: [
      agent({
        name: 'researcher',
        provider: 'openai',
        model: 'gpt-4o-mini',
        system: 'Research the assigned topic and return concise findings.',
      }),
      agent({
        name: 'writer',
        provider: 'openai',
        model: 'gpt-4o',
        system: 'Turn approved findings into polished written output.',
      }),
    ],
  })
);

console.log(contentTeam.id); // `create()` returns the SwarmState
```

### `SwarmConfig` fields

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `strategy` | `SwarmStrategy` | yes | Coordination strategy (below) |
| `manager` | `AgentConfig` | yes | Lead agent |
| `workers` | `AgentConfig[]` | yes | Agents that execute subtasks |
| `maxTurns` | `number` | no | Strategy-specific turn cap (below); defaults to the number of workers plus one |
| `maxParallelDelegations` | `number` | no | Concurrent delegations the `supervisor` strategy allows; defaults to the number of workers (at least 1) |
| `maxConcurrentAgents` | `number` | no | Cap on agents the swarm admits at once; spawning beyond it fails with `Max concurrent agents (N) reached` |
| `tokenBudget` | `number` | no | Per-run observed token budget shared by manager and workers; `0` blocks all runs, omitted means unlimited |

`tokenBudget` is checked before each model request, so a request already in flight can overshoot it. It is not a hard billing cap.

### `SwarmStrategy`

| Value | Behavior | What `maxTurns` limits |
|-------|----------|------------------------|
| `round-robin` | Agents take turns in rotation | Total rotations executed |
| `supervisor` | The manager delegates to workers with tool calls | Delegations the manager may issue |
| `dynamic` | The manager picks which agent speaks next | Speaker choices the manager may make |

<Aside type="note">
  The daemon creates the manager and worker agents from the config when the swarm is created. You do not call `client.agents.create()` for them.
</Aside>

## Run a Swarm

```typescript
const run = await client.swarms.run(contentTeam.id, {
  text: 'Write a comprehensive article about renewable energy',
});

if (run.result.status === 'success') {
  console.log('Result:', run.result.data?.text);
}

console.log('Tokens used:', run.swarm.tokenUsage.totalTokens);
console.log('Status:', run.swarm.status);
```

`swarms.run()` blocks until the swarm finishes. Runs of one swarm are serialized, and the daemon answers `503` when its global run limit (`ANIMAOS_RS_MAX_CONCURRENT_RUNS`, default 8) is exhausted. If the HTTP response times out or the client disconnects, an admitted swarm run still completes inside the daemon.

### Retrying a swarm run safely

With durable step persistence, a retried swarm run can reuse completed tool work. Send one stable retry key in the request metadata and repeat it when retrying the same logical task.

```typescript
await client.swarms.run(contentTeam.id, {
  text: 'Coordinate the release checklist',
  metadata: { retryKey: 'release-checklist-2026-05-05' },
});
```

The coordinator scopes that key for manager and worker turns, and each agent derives deterministic tool-step keys from it. Fresh runs should omit the key or use a new one.

<Aside type="note">
  With `ANIMAOS_RS_CONTROL_PLANE_FILE` or Postgres mode, the daemon restores swarm registrations and latest snapshots after a restart. Interrupted in-flight runs are reported as failed and should be retried intentionally.
</Aside>

### `SwarmRunResponse`

| Field | Type | Description |
|-------|------|-------------|
| `swarm` | `SwarmState` | Final swarm state after execution |
| `result` | `DaemonTaskResult<{ text: string }>` | Synthesized result: `status`, `data`, `error`, `durationMs` |

### `SwarmState`

| Field | Type | Description |
|-------|------|-------------|
| `id` | `UUID` | Swarm identifier |
| `status` | `'idle' \| 'running' \| 'completed' \| 'failed'` | Current status |
| `agentIds` | `string[]` | IDs of every agent in the swarm |
| `messages` | `AgentMessage[]` | Agent-to-agent messages (`id`, `from`, `to`, `content`, `timestamp`) |
| `results` | `TaskResult[]` | Results collected so far |
| `tokenUsage` | `TokenUsage` | Cumulative token consumption |
| `startedAt`, `completedAt` | `number` (optional) | Unix timestamps (ms) |

## Get Swarm State

```typescript
const state = await client.swarms.get(contentTeam.id);
console.log(state.status, state.agentIds, state.tokenUsage.totalTokens);
```

The daemon also lists swarms with `GET /api/swarms`; the SDK has no helper for it, so use `client.requestJson('/api/swarms')`.

## Live Events

`client.swarms.subscribe(swarmId, { signal })` yields the swarm's SSE events. Event names, payload shapes and monitoring patterns are on [Event Streaming](/sdk/swarms/events/).

## Full Example: Content Pipeline

```typescript
import { agent, swarm, createDaemonClient } from '@animaOS-SWARM/sdk';

const client = createDaemonClient();

const pipeline = await client.swarms.create(
  swarm({
    strategy: 'supervisor',
    maxTurns: 15,
    manager: agent({
      name: 'editor',
      provider: 'openai',
      model: 'gpt-4o',
      system: 'You are a senior editor. Review drafts, request revisions, and approve final copy.',
    }),
    workers: [
      agent({
        name: 'researcher',
        provider: 'openai',
        model: 'gpt-4o-mini',
        system: 'Research topics thoroughly. Cite sources when possible.',
      }),
      agent({
        name: 'writer',
        provider: 'openai',
        model: 'gpt-4o',
        system: 'Write engaging, accurate content based on approved research.',
      }),
    ],
  })
);

// Subscribe first, then run, so no early events are missed.
const controller = new AbortController();
const watcher = (async () => {
  for await (const { event, data } of client.swarms.subscribe(pipeline.id, {
    signal: controller.signal,
  })) {
    if (typeof data === 'object' && data !== null && 'agentName' in data) {
      console.log(`[${data.agentName}] ${event}`);
    }
  }
})().catch((error) => {
  if (!(error instanceof Error && error.name === 'AbortError')) throw error;
});

const result = await client.swarms.run(pipeline.id, {
  text: 'Write a 500-word blog post about the James Webb Space Telescope',
});
controller.abort();
await watcher;

console.log('Final article:', result.result.data?.text);
```
