## Evaluate Before Writing

```typescript
const evaluation = await client.memories.evaluate({
  agentId: 'AGENT_ID',
  agentName: 'researcher',
  type: 'fact',
  content: 'Something happened',
  importance: 0.5,
});

console.log(evaluation.decision, evaluation.reason, evaluation.score);
```

`evaluate()` takes the same fields as `create()` plus optional `minContentChars` and `minImportance`, and stores nothing. It returns a `MemoryEvaluation`: `decision` (`store`, `merge` or `ignore`), `reason`, `score`, `suggestedImportance` and `duplicateMemoryId` for a merge.

## Evaluate and Store

```typescript
const outcome = await client.memories.addEvaluated({
  agentId: 'AGENT_ID',
  agentName: 'researcher',
  type: 'fact',
  content: 'User prefers concise release notes',
  importance: 0.4,
  tags: ['preference'],
  minContentChars: 8,
  minImportance: 0.1,
});

console.log(outcome.evaluation.decision, outcome.memory?.id);
```

The outcome holds the `evaluation` and the stored `memory`, which is `null` unless the decision was `store`; duplicate or low-value candidates add no new record.

## Evidence Trace

```typescript
const trace = await client.memories.trace('MEMORY_ID');

console.log(trace.memory.content);
console.log(trace.relationships.length, trace.entities.length);
```

The trace returns the memory, the relationships that cite it and the entities involved. Use it when the app needs to explain why a memory matters.

## Retention and Cleanup

```typescript
const report = await client.memories.applyRetention({
  minImportance: 0.2,
  maxMemories: 1000,
  maxAgeMillis: 30 * 24 * 60 * 60 * 1000,
  decayHalfLifeMillis: 24 * 60 * 60 * 1000,
});

console.log(report.decayedMemories.length, report.removedMemoryIds.length);
```

All four fields are optional.

| Field | Description |
|-------|-------------|
| `maxAgeMillis` | Remove memories older than this |
| `minImportance` | Remove memories below this importance |
| `maxMemories` | Keep at most this many |
| `decayHalfLifeMillis` | Half-life for importance decay |

The report has `decayedMemories` (`memoryId`, `previousImportance`, `newImportance`), `removedMemoryIds` and `removedRelationshipIds`.

## Readiness

```typescript
const ready = await client.memories.readiness();

console.log(ready.passed, ready.embeddings.vectorCount);
console.log(ready.embeddings.status, ready.embeddings.done, ready.embeddings.total);
console.log(ready.externalProvider?.status);
console.log(ready.evaluation.passedChecks, '/', ready.evaluation.totalChecks);
```

### `MemoryReadiness`

| Field | Type | Description |
|-------|------|-------------|
| `passed` | `boolean` | Overall status |
| `embeddings` | `MemoryEmbeddingStatus` | Embedding engine status |
| `externalProvider` | `ExternalMemoryProviderStatus` (optional) | The external memory provider beside the local store (`none` by default); absent from older daemons |
| `evaluation` | `MemoryEvalReport` | Baseline eval harness result: `passed`, `totalChecks`, `passedChecks`, `failureMessages`, `cases` |

### `MemoryEmbeddingStatus`

| Field | Type | Description |
|-------|------|-------------|
| `enabled` | `boolean` | Whether embeddings are active |
| `provider`, `model` | `string` | Embedding provider and model |
| `dimension` | `number` | Vector size |
| `vectorCount` | `number` | Vectors stored |
| `persisted` | `boolean` | Whether vectors are persisted |
| `storageFile` | `string \| null` | Vector store file, when any |
| `status` | `MemoryEmbeddingLoadStatus` | `downloading`, `rebuilding`, `ready`, `fallback` or `off`; the search model loads in the background after boot |
| `done`, `total` | `number` | Memories with a vector from the active embedder, out of those to embed (`rebuilding` shows progress) |
| `reason` | `string` (optional) | Why search fell back to basic search; only with `fallback` |

`ExternalMemoryProviderStatus` is `{ id, status: 'ready' | 'unavailable', reason? }`. Only `none` is built in today.

## Entities and Relationships

Entities and relationships form an explicit graph that recall uses for relationship scoring.

```typescript
const entity = await client.memories.createEntity({
  kind: 'user',
  id: 'user-42',
  name: 'Alice',
  aliases: ['al', 'ali'],
  summary: 'A power user who prefers CLI tools.',
});

const relationship = await client.memories.createRelationship({
  sourceKind: 'agent',
  sourceAgentId: 'agent-a',
  sourceAgentName: 'researcher',
  targetKind: 'agent',
  targetAgentId: 'agent-b',
  targetAgentName: 'writer',
  relationshipType: 'collaborator',
  strength: 0.9,
  confidence: 0.85,
});

const entities = await client.memories.entities({ kind: 'user', limit: 50 });
const relationships = await client.memories.relationships({
  agentId: 'agent-a',
  relationshipType: 'collaborator',
  minStrength: 0.5,
  limit: 10,
});

console.log(entity.id, relationship.relationshipType, entities.length, relationships.length);
```

`createEntity` and `createRelationship` create or update. Entity `kind` and relationship `sourceKind` and `targetKind` are one of `agent`, `user`, `system` or `external` (relationship kinds default to `agent`).

### `NewAgentRelationshipInput`

Required: `sourceAgentId`, `sourceAgentName`, `targetAgentId`, `targetAgentName`, `relationshipType`. Optional: `sourceKind`, `targetKind`, `summary`, `strength`, `confidence`, `evidenceMemoryIds`, `tags`, `roomId`, `worldId`, `sessionId`.

### `AgentRelationshipOptions`

Filters for `relationships()`: `agentId`, `entityId`, `sourceKind`, `sourceAgentId`, `targetKind`, `targetAgentId`, `relationshipType`, `roomId`, `worldId`, `sessionId`, `minStrength`, `minConfidence`, `limit`.

### `MemoryEntity`

`kind`, `id`, `name`, `aliases`, `summary` (`string | null`), `createdAt`, `updatedAt`. `entities()` filters by `entityId`, `kind`, `name`, `alias` and `limit`.

<Aside type="note">
  Retrieval and write-side operations complement each other. `search()` and `recall()` find memory; evaluation, retention, entities and relationships keep that memory healthy. Deleting entities and editing individual records is covered in [Core Memory & Export](/sdk/memories/core/).
</Aside>
