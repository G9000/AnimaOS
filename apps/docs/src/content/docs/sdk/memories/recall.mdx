Memory retrieval has three levels:

- `search()` for keyword lookup with filters
- `recall()` for fused ranking across lexical, vector, relationship, temporal, recency and importance signals
- `recent()` for freshness

<CardGrid>
  <Card title="Search">
    Use `search()` for direct keyword or filter-driven lookup. Results are flat memories with a `score`.
  </Card>
  <Card title="Recall">
    Use `recall()` when you want a fused ranking with per-signal scores. Results nest the memory under `memory`.
  </Card>
  <Card title="Recent">
    Use `recent()` when freshness matters more than retrieval scoring.
  </Card>
</CardGrid>

## Search

```typescript
const results = await client.memories.search('daemon memory', {
  agentName: 'researcher',
  type: 'fact',
  limit: 5,
  minImportance: 0.5,
});

for (const result of results) {
  console.log(result.score, result.content, result.tags);
}
```

`MemorySearchResult` is a `Memory` plus `score`, so read `result.content`, not `result.memory.content`. The daemon also serves the same search at `GET /api/search`.

## Recent Memories

```typescript
const memories = await client.memories.recent({
  agentId: 'AGENT_ID',
  scope: 'shared',
  limit: 20,
});
```

For one agent's most recent memories without other filters, `client.agents.recentMemories(agentId, { limit })` is also available.

## Fused Recall

```typescript
const results = await client.memories.recall('evidence probe', {
  entityId: 'user-1',
  agentId: 'AGENT_ID',
  temporalLimit: 7,
  limit: 3,
});

for (const r of results) {
  console.log(r.score, r.memory.content);
  console.log(r.lexicalScore, r.vectorScore, r.relationshipScore);
}
```

## How to Read Recall Scores

Recall combines:

- lexical match (BM25)
- vector similarity from the configured embedder
- relationship proximity to `entityId`
- temporal relevance
- recency
- stored importance

You do not need the weighting math. What matters is that recall is intentionally richer than search: each result exposes `lexicalScore`, `vectorScore`, `relationshipScore`, `temporalScore`, `recencyScore` and `importanceScore` next to the fused `score`, so you can see why a memory surfaced.

<Aside type="note">
  Vector scores depend on the embedder. The default `fastembed` model loads in the background after startup; until it is ready (or if it fails to load), the daemon uses hashed vectors and keyword search. `client.memories.readiness()` reports the state.
</Aside>

<Aside type="tip">
  Reach for `search()` when you already know what you are looking for. Reach for `recall()` when the system should infer the best supporting memories from several signals.
</Aside>
