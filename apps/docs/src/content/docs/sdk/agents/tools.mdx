Tools are executed by the Rust daemon. The SDK does not run tool code: it tells the daemon which tools an agent may use, by name or by JSON descriptor.

<CardGrid>
  <Card title="By name">
    Pass the name of a tool the daemon has registered, for example `'memory_search'`.
  </Card>
  <Card title="By descriptor">
    Pass `{ name, description, parameters, examples }` to control what the model sees.
  </Card>
  <Card title="Granted per agent">
    A tool runs only for agents whose `tools` list includes it, and approval policy still applies.
  </Card>
</CardGrid>

## `AgentToolInput`

Each entry in `AgentConfig.tools` is an `AgentToolInput`:

```typescript
type AgentToolInput =
  | string
  | {
      name: string;
      description?: string;
      parameters?: Record<string, unknown>;
      examples?: DaemonToolDescriptor['examples'];
    };
```

- A plain string is the name of a tool registered in the daemon.
- An object supplies the name plus an optional description, JSON Schema `parameters`, and few-shot `examples`.

## Discover Registered Tools

Ask the daemon which tool handlers it has registered:

```typescript
import { createDaemonClient } from '@animaos/sdk';

const client = createDaemonClient();
const capabilities = await client.capabilities();

for (const tool of capabilities.tools) {
  console.log(`${tool.category}: ${tool.name} - ${tool.description}`);
}
```

Each `DaemonCapabilityTool` has a `name`, `description`, a `category` (`workspace`, `terminal`, `memory`, `team`, `research`, `productivity`, `browser`, `documents` or `utility`) and a `requirements` list. Registered tools include, among others, `memory_search`, `memory_add`, `core_memory`, `recent_memories`, `web_fetch`, `web_search`, `exa_search`, `read_file`, `write_file`, `edit_file`, `glob`, `grep`, `list_dir`, `bash`, `bg_start`, `todo_write`, `load_skill`, `create_automation` and `send_message`; call `capabilities()` for the live list. See [Workspace & Capabilities](/sdk/workspace/) for the rest of that response.

<Aside type="note">
  A registered handler is not a connection check or a permission grant. It only shows what the daemon can execute, and many tools need a configured workspace, a connector or an owner opt-in first.
</Aside>

## Register Tools on an Agent

```typescript
import { agent, createDaemonClient } from '@animaos/sdk';

const client = createDaemonClient();

const researcher = await client.agents.create(
  agent({
    name: 'researcher',
    provider: 'openai',
    model: 'gpt-4o-mini',
    system: 'Use tools when needed.',
    tools: [
      'memory_search',
      {
        name: 'web_fetch',
        description: 'Fetch and summarize a URL',
        parameters: {
          type: 'object',
          properties: {
            url: { type: 'string', description: 'URL to fetch' },
          },
          required: ['url'],
        },
      },
    ],
  })
);
```

Change an agent's tools later with `client.agents.update(id, { tools: [...] })`; an empty array clears them.

## Practical Split

- Use a tool name when the daemon already registers the capability you need.
- Use a descriptor when you want to control the description or schema the model sees.
- Keep tool execution in the daemon instead of orchestrating it from the SDK caller.
- Tools that change files, run commands, reach the network or delegate are subject to the agent's [approval policy](/sdk/approvals/), which by default asks before running commands (`exec`).
