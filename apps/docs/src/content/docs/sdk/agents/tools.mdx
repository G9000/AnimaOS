Tools are executed by the Rust daemon. The SDK does not run tool code: it only tells the daemon which tools an agent may use, by name or by JSON descriptor.

<CardGrid>
  <Card title="By name">
    Pass the name of a tool the daemon has already registered, for example `'memory_search'`.
  </Card>
  <Card title="By descriptor">
    Pass `{ name, description, parameters, examples }` to describe the tool the model should see.
  </Card>
  <Card title="Registration">
    Set `tools` on the agent config before you register the agent with the daemon.
  </Card>
</CardGrid>

## `AgentToolInput`

Each entry in `AgentConfig.tools` is an `AgentToolInput`:

```typescript
type AgentToolInput =
  | string
  | {
      name: string;
      description?: string;
      parameters?: Record<string, unknown>;
      examples?: DaemonToolDescriptor['examples'];
    };
```

- A plain string is the name of a tool registered in the daemon.
- An object supplies the name plus an optional description, JSON Schema `parameters`, and few-shot `examples` for the model.

## Discover Registered Tools

Ask the daemon which native tool handlers it has before you reference them:

```typescript
import { createDaemonClient } from '@animaOS-SWARM/sdk';

const client = createDaemonClient();
const capabilities = await client.capabilities();

for (const tool of capabilities.tools) {
  console.log(`${tool.category}: ${tool.name} - ${tool.description}`);
}
```

<Aside type="note">
  A registered handler is not a connection check or a permission grant. It only shows what the daemon can execute.
</Aside>

## Register Tools on an Agent

```typescript
import { agent, createDaemonClient } from '@animaOS-SWARM/sdk';

const client = createDaemonClient();

const researcher = await client.agents.create(
  agent({
    name: 'researcher',
    provider: 'openai',
    model: 'gpt-4o-mini',
    system: 'Use tools when needed.',
    tools: [
      'memory_search',
      {
        name: 'web_fetch',
        description: 'Fetch and summarize a URL',
        parameters: {
          type: 'object',
          properties: {
            url: { type: 'string', description: 'URL to fetch' },
          },
          required: ['url'],
        },
      },
    ],
  })
);
```

You can change an agent's tools later with `AgentUpdateInput.tools`.

## Practical Capability Split

- use a tool name when the daemon already registers the capability you need
- use a descriptor when you want to control the description or schema the model sees
- keep runtime-heavy behavior in the daemon instead of pushing orchestration into the SDK caller

<Aside type="tip">
  The SDK gives you typed configuration. The actual runtime execution happens inside the daemon, not inside the SDK package.
</Aside>
