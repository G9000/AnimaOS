This page is the practical agent loop: create an agent, run work through it, inspect the updated snapshot, change or remove it, and use retry keys correctly when the daemon supports durable step reuse.

<CardGrid>
  <Card title="Create">
    Register an agent in the daemon with `client.agents.create()`.
  </Card>
  <Card title="Run">
    Send one `Content` payload with `client.agents.run()`.
  </Card>
  <Card title="Inspect">
    Read the updated snapshot, token usage, and recent memories.
  </Card>
  <Card title="Change or retire">
    `update()` patches the model, prompt and tools; `remove()` deletes the agent.
  </Card>
</CardGrid>

## Create an Agent

```typescript
import { agent } from '@animaos/sdk';

const researcher = await client.agents.create(
  agent({
    name: 'researcher',
    provider: 'openai',
    model: 'gpt-4o-mini',
    system: 'You are a concise research assistant.',
  })
);
```

The daemon stores the agent and returns an `AgentSnapshot`. With a control-plane file or Postgres configured, registered agents survive a daemon restart.

## Run an Agent

```typescript
const execution = await client.agents.run(researcher.state.id, {
  text: 'Summarize the latest database durability changes.',
});

console.log(execution.result.status);
console.log(execution.agent.state.tokenUsage.totalTokens);
```

The response carries both the task result and the updated snapshot. This call blocks until the run ends; for long work, send the message to a [session](/sdk/sessions/) instead and follow the run.

## Inspect and Re-read

```typescript
const snapshot = await client.agents.get(researcher.state.id);
const recent = await client.agents.recentMemories(researcher.state.id, { limit: 10 });

console.log(snapshot.state.status, recent.length);
```

Use `listSummaries()` when you only need state and counts for many agents.

## Update and Remove

```typescript
await client.agents.update(researcher.state.id, {
  system: 'You are a concise research assistant. Cite sources.',
  tools: ['memory_search', 'web_fetch'],
});

await client.agents.remove(researcher.state.id);
```

`update()` returns the updated snapshot. `remove()` resolves with no value and fails with `409` while one of the agent's runs is running; messages still waiting to start are cancelled.

## Safe Retry Keys

If the daemon has durable step persistence, completed tool steps can be reused when you retry the same logical request with the same key.

```typescript
const run = await client.agents.run(researcher.state.id, {
  text: 'Compile the release notes.',
  metadata: { retryKey: 'release-notes-2026-05-05' },
});
```

- Reuse the same key only when retrying the same logical work.
- Omit the key or generate a new value for a fresh request.
- This is step reuse, not a mid-turn resume after a process crash. A daemon restart marks interrupted runs for review instead of replaying them.

<Aside type="note">
  Retry behavior depends on daemon persistence. The SDK only gives you a typed way to send the metadata; the daemon decides whether durable reuse is available.
</Aside>
